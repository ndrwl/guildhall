# `internal/config`

## Contract

`Parse` refuses unknown keys, newer schemas and credentials, applies defaults and validates (`docs/configuration.md`).
Repository paths follow the owner-machine contract ([repository paths](../decisions/repository-paths-are-absolute.md)): POSIX-rooted and rooted Windows drive-letter paths are accepted on every host; relative, drive-relative and backslash-prefixed UNC paths are refused.
Duplicate comparison normalizes dot segments and, for drive paths, separators and drive-letter case independently of the parsing host.
`EncodeManaged` and `ParseCombined` frame and verify the separate managed file and refuse inline managed settings beside it ([managed publication](../decisions/managed-publication-separate-from-director-config.md)).
`Load` follows the filesystem fallback and error rules in [configuration](../configuration.md).

`ShippedProfiles` are the six role profiles the release ships, `researcher`, `planner`, `builder`, `reviewer`, `rebaser` and `designer`, each `Profile{Adapter: "claude"}` but `designer`, `Profile{Adapter: "claude", Effort: "high"}`; `Parse` of a Director config, before validating it, adds each one the config does not declare to `Profiles`, so every check of a declared profile, `Profile`, `CheckProfiles`, repository grants, `claude_skills_profile_<name>`, `quality_judge_profiles`, `EffectiveGrant` and the `director start` preflight, accepts the shipped names; a copy's section of a shipped name replaces it whole, and a Steward config gets none ([decision](../decisions/role-profiles-outside-the-digest.md)).
A config built without `Parse` has only the profiles it is given.
`Profile` and `CheckProfiles` refuse an unknown profile name (`ErrUnknownProfile`).
`CheckArtisanAdapters` checks profile references, then refuses the first Artisan step that names no profile and whose effective profile (`workflow.EffectiveProfile`) the config lacks (`ErrMissingAdapter`), naming the workflow and step; for a step type with a role profile (`workflow.RoleProfile`), which only a config built without `Parse` can lack, the remedy is to declare `[profile.<role>]` or set a profile on that step, and for a step type with none it is to set a profile on that step in a custom workflow.
It is read-only, does not launch anything, and does not require an adapter for other actors.
Explicit fake profiles remain valid; no default adapter fallback is supported.
A profile's `AllowedTools` is a pointer to its `allowed_tools` list in order: nil when the key is unset, and non-nil, possibly empty, when it is set, which `Parse` decides with the decode metadata's `IsDefined`, so `allowed_tools = []` survives a JSON round trip as set (`AllowedToolsSet`, `AllowedToolsList`); `Parse` refuses an entry `CheckAllowedTool` refuses, a tool name with an optional non-empty parenthesised specifier and no control characters that does not allow every shell command (`Bash`, `Bash(*)`, `Bash(:*)`), and a duplicate, naming the profile; profiles are read only from the copy's own config, never from `managed.toml`.
A temporary grant for one task is a store record, not config: [task grants](../tasks.md#task-grants) check their rules with the same `CheckAllowedTool` and never change `config.toml` ([decision](../decisions/task-grants.md)).
`StallInterval` is the effective `stall_interval` [setting](../configuration.md#settings) as a duration, `DefaultStallInterval` (15 minutes) when unset and zero for `0s`; `Parse` refuses a managed or local value that is not a nonnegative Go duration, and `StallInterval` returns that error for a config built without `Parse`.
`ChecksRefresh` is the effective `checks_refresh` setting the same way, `DefaultChecksRefresh` (1 minute) when unset and zero for `0s`.
`CILogLimit` is the effective `ci_log_limit` setting in bytes, `DefaultCILogLimit` (5 MiB) when unset and zero, fetching no logs, for `0`: whole bytes with an optional 1024-based `KiB`, `MiB`, `KB` or `MB` suffix, from 64 KiB to 100 MiB; `Parse` refuses a negative, fractional, padded, out-of-range or unknown-suffix managed or local value naming the key, and `ci_log_limit_test.go` pins the default, each format, `0`, the refusals in both sections and a local override of a managed value; it was written with the implementation and not run red.
`ArtisanWorkspaceCloseAfter` is the effective `artisan_workspace_close_after` setting the same way, `DefaultArtisanWorkspaceCloseAfter` (5 minutes) when unset and zero, never closing automatically, for `0` or `0s`; `Parse` refuses an invalid or negative managed or local value naming the key, and `workspace_close_test.go` pins those cases.
`LockWait` is the effective `lock_wait` setting, `DefaultLockWait` (30 seconds) when unset; `Parse` refuses a managed or local value that is not a positive Go duration, and `LockWait` returns that error for a config built without `Parse`.
`GuardRails` returns the [guard rails](../director.md#guard-rails): the listed repositories in config order, their effective merge requirements (`MergeRequires.Effective`, every key set), and the effective `max_running_attempts` and `max_attempts_per_day` settings, `DefaultMaxRunningAttempts` (4) and `DefaultMaxAttemptsPerDay` (40) when unset; `Parse` refuses a managed or local `max_running_attempts` that is not a positive whole number written plainly, and a `max_attempts_per_day` that is not a whole number written plainly, where `"0"` is accepted and means no daily cap, and `GuardRails` returns that error, naming the key, for a config built without `Parse`.
`quality_audit_sample` is deprecated and has no effect, since the Guildmaster's audit is retired ([decision](../decisions/retire-quality-audit.md)): `Quality` still parses it into `AuditSample`, default 5, which nothing reads but the status feed, and `Config.Deprecations` returns one warning for each of the managed and local sections that sets it, saying it has no effect and naming its replacement, `[director] retrospective_after_merges`; `director start` prints each as a `config: warning:` preflight line.
`Quality` returns the effective [quality settings](../configuration.md#quality-settings), each its `DefaultQuality…` value when unset, with `skill_edits_need_approval` parsed for the later lesson-proposal work and read by nothing yet, and `judge_profiles` the declared profiles `quality_judge_profiles` lists, comma-separated with optional spaces; `Parse` refuses a managed or local value that is not `on` or `off` for a switch, not a whole number written plainly for a budget or the audit sample, not a positive whole number for runs per task, not `off` or `on-change-and-release` for reference runs, or not a positive dollar amount with at most two decimals for the cost cap, naming the key, and refuses effective reference runs with no cost cap and judge profiles that are not profile names, are named twice or are not declared; `Quality` returns the same errors for a config built without `Parse`.
`Quality.Judge` chooses a [judge session](../decisions/quality-rubric.md)'s `JudgeChoice`, a family being an adapter: excluding the builder's profile and failed profiles, and refusing with `ErrNoJudge` and a reason when no eligible profile is listed (including an unset list), the first listed profile of an adapter other than the builder's while `JudgeSeparateFamily` is on, else the first listed; `SeparateFamily` is true only when the builder's adapter is known and differs, and `Reason` says why it is not: none of another family listed, every one of another family failed, the setting off, or the builder unknown.
`Repository.Merge.Requires` holds the [`[repository.merge.requires]`](../configuration.md#merge-requirements) booleans as `*bool`, nil for a key the config does not set; its `Guildmaster`, `Artisan`, `CI` and `Open` methods read nil as true, so the zero value, like a config without the section, requires everything.
`Repository.Merge` also holds the [rebase settings](../configuration.md#rebase-settings): `ReapproveAfterRebase`, a `RebaseKind` (`RebaseNoConflicts`, `RebaseMinorConflicts`, `RebaseMajorConflicts`, `RebaseNever`, ordered by `Rank`), read through `Reapprove`, `DefaultReapproveAfterRebase` (`major_conflicts`) when unset, and `MinorConflictFiles` and `MinorConflictLines`, read through `MinorFiles` and `MinorLines`, 3 and 50 when unset; `NeedsReapproval(k)` reports whether kind `k` is at or above the threshold.
`Parse` refuses an unknown kind, `never` unless `Requires.Artisan()` holds, and a count below 1, naming the repository.

`ListedRepository` returns a listed repository or an error wrapping `ErrRepositoryNotListed` that names the id; every command acting on a repository finds it there.
`HerdrSession` is the effective `herdr_session` setting, `""` when unset; `Parse` refuses a managed or local value that is `default` or not a Herdr session name.
A repository's `NoCI` is its `no_ci` setting, `false` by default.
A repository's `Profiles` are its repository grants, `[repository.profiles.<name>]`, each a `RepositoryProfile` whose `AllowedTools` are added to that profile's effective grant for the repository's tasks ([D93](../decisions/task-grants.md)); omitted from JSON when unset, so a config without them keeps its digest, and refusing an unknown key under a profile; `Parse` refuses a rule `CheckAllowedTool` refuses, a duplicate within one repository profile, a profile the config neither declares nor gets shipped and a profile whose adapter is not `claude`, naming the repository and profile.
`TestProfileAllowedToolsEmptyIsSet`, `TestRepositoryProfileGrant` and `TestInvalidRepositoryProfileGrantRefused` check these.
A repository's `Kinds` is its [`[repository.kinds]`](../configuration.md#repositories) table, omitted from JSON when unset so a config without it keeps its digest; `Parse` reads `TaskKindTable` to refuse the key of a row that runs `Workflow` (`feature`), any key not in the table, listing the others ("bug and hallmark"), and a value that is not a workflow name.
`TaskKindTable` is the one table of task kinds, feature, bug and hallmark in that order, each row with its name, its `task new --help` description, its default workflow and whether it runs `Workflow`; `TaskKinds` is the table's names and `TaskKindRowOf` looks a row up by name.
`Repository.TaskKindWorkflow` reads the row to name the workflow a kind runs: `Workflow` for a feature, `Kinds[<kind>]` or the row's default workflow for a bug or a hallmark, and none for an unknown kind. `TestTaskKindTable` checks `TaskKinds` is the table's names in order and that exactly one row, the first, runs `Workflow`.
`Director` is the optional [`[director]` table](../configuration.md#the-director-table): an adapter that is an id when set, a config-relative role path, an `idle_after` that is a positive Go duration when set, and none in a Steward config; it is omitted from JSON when unset, as `idle_after` is, so a config without them keeps its digest.
`IdleAfter` returns the effective `[director] idle_after`, `DefaultIdleAfter` (5 minutes) when unset.
A Steward config runs the default session settings ([Steward](../steward.md#lifecycle)): its `[director]` table and those keys under `[steward]` are refused, and `Parse` refuses `wake_quiet` in its `[local]` or `[managed]` with `wake_quiet is a director setting, not the steward's`; `TestStewardRunsTheDefaultSessionSettings` pins each refusal and that `wake_max_delay` stays accepted, written red-first for `wake_quiet`.
`Web` is the optional [`[web]` table](../configuration.md#the-web-table): a required `address` with a host and a port from 1 to 65535, and an optional `guildmaster` login of printable characters with no space, at most `MaxWebLoginBytes`; none in a Steward config; omitted from JSON when unset, so a config without it keeps its digest. Whether the host resolves to Tailscale addresses is checked when the server binds ([`internal/web`](web.md)), so a config parses with no network. `web_test.go` pins the parse, the digest and the refusals; written with the implementation.
`Handoff` returns the effective [automatic handoff](../director.md#automatic-handoff) triggers: `handoff_after_tasks` (0, off, when unset), `handoff_context_percent` (`DefaultHandoffContextPercent`, 70, when unset; 0 is off) and `handoff_idle` (`0s`, off, when unset); `Parse` refuses a negative task count, a percent outside 0 to 100 and an idle period that is not a non-negative duration.
`Maintenance` returns the effective [maintenance](../director.md#maintenance) cadences: `note_audit_every_sessions` (`DefaultNoteAuditEverySessions`, 3, when unset) and `hallmark_after_merges` (`DefaultHallmarkAfterMerges`, 4, when unset), 0 being off; `Parse` refuses a negative value, and both are omitted from JSON when unset; `TestDirectorMaintenanceCadences` checks them.

The setting registry declares every [setting](../configuration.md#setting-scopes) once with its `Scope`, `ScopeTask` or `ScopeMachine`, and its value check; `validate` runs each check on the managed and local sections, and `SettingScope` returns a key's scope, or false for a key it does not name, `claude_skills_profile_<name>` being machine-wide for any name.
`WithTaskOverrides(overrides)` returns a copy of a valid config whose `Local` takes each applicable override, key to value, so the effective value is the task override, then local, then managed, a managed key that is not overridable still winning; it never mutates its receiver, leaves `step.` keys to the workflow and `merge.requires.` keys (or `repository.merge.requires.`) to `MergeRequires.WithTaskOverrides`, out of `Local` and its skips, returns an error only for an invalid receiver, and returns each override that does not apply as a `Skipped` with its reason, in key order: an unknown, machine-wide, kept-out (`[repository.merge]`, `[director]`, repository identity) or pinned key, a value its check refuses, or one that leaves the config invalid beside the others, each kept in key order when only some of them together are valid.
`CheckTaskOverride(key, value)` refuses such an override alone, wrapping `ErrNotTaskOverridable` for a machine-wide, kept-out or pinned key and `ErrUnknownSetting` for an unknown one.
It accepts `merge.requires.<key> = true`, or `repository.merge.requires.<key>`, for each of the four merge requirements, judged before the rest of `[repository.merge]` is kept out, and refuses `false` as making requirements looser, any other value as not a boolean and an unknown requirement naming the four.
`MergeRequires.WithTaskOverrides(overrides)` returns a copy of the requirements with each such `true` set, the names it added (those explicitly off before, in documented order; one already on is a silent no-op) and each merge-requires override that does not apply as a `Skipped`, ignoring every other key and never mutating its receiver, so the read side enforces stricter-only whatever the CLI checked; `merge_override_test.go` checks both.
`scope_test.go` checks that every exported `*Key` constant is registered, each key's scope, precedence, that the receiver is unchanged, each skip and refusal reason and an invalid combination; it was written with the implementation and not run red.

`EffectiveEffort(explicit)` returns a nonempty explicit Director/profile effort unchanged, otherwise the effective `default_effort` managed/local setting, or `medium` when absent.
It does not mutate the config or inject defaults into its digest; it is for validated configs.
`Parse` and `ParseCombined` refuse either section's `default_effort` unless it is exactly `low`, `medium`, `high`, `xhigh` or `max`, even if overridden; normal managed/local precedence applies.
Explicit session/profile settings remain runtime-validated, so fake accepts any value while Claude refuses unsupported settings before launch.

`ClaudeSkills` resolves typed, versioned managed/local skill policies with explicit profile binding, preset expansion and deterministic control digests.
See the focused [Claude policy contract](config-claude-skills.md) for validation, source/plugin limits and rendering ownership.

## Tests

`TestArtisanAdapterAdmission` in `artisan_test.go` rejects the profile-less shipped workflow in a manually constructed config without the role profiles, even when it contains a local `default_adapter` value of fake, Claude or mock; that setting does not provide admission.
It accepts explicit profiles for those adapters, removes each Artisan step's profile in turn to assert a step-named refusal, and checks unknown-profile errors.
`TestArtisanAdapterRemedyNamesTheRoleProfile` refuses the shipped default in a config built without the reviewer's profile with the remedy naming `[profile.reviewer]`, and a refute step with the custom-workflow remedy; a parsed Director config with no `[profile.*]` admits the default and still refuses the refute step.
`TestShippedDirectorSelectsRealArtisan` loads the example Director config, which declares no profiles, resolves each repository's workflow for each task kind, applies repository overrides, validates and checks admission, and asserts every Artisan step's effective profile is a Claude profile.
`TestShippedProfiles` in `profile_test.go` checks the shipped profiles are present after `Parse` of a Director config and absent from a Steward's, that a copy section replaces one whole, and that repository grants on `builder`, `reviewer` and `rebaser`, `claude_skills_profile_reviewer` and `quality_judge_profiles` accept shipped names with no copy section.
`TestTaskKindWorkflow` pins each kind's workflow with and without a kinds table and that a config without one encodes no `Kinds`; `TestValidationRefusals` covers a `feature` key, an unknown kind and an invalid `bug` or `hallmark` workflow name.
These focused configuration tests were added after the implementation; the original CLI regressions drove the change red first.
They do not test default-adapter precedence or malformed-default validation, which are not supported admission paths.

`claude_skills_test.go` was run red before implementation (missing parser/resolver methods), then green; `claude_defaults_test.go` adds semantic shipped-example, full matrix and identity regression coverage afterward.

`effort_test.go` was written before implementation: default/local/managed/overridden effort, explicit override, malformed values and separate managed-file precedence; its first run failed to compile because `EffectiveEffort` did not yet exist, then passed with the implementation.
