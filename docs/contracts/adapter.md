# `internal/adapter`

## Contract

The spec, identity, capabilities and versioned result file, completion only from that file (`docs/adapters.md`).
`Spec.Copy` and `Spec.Profile` reference the Director's profile ([Artisan permissions](../adapters.md#artisan-permissions)); no rule list is transported.
`ProfileTools` loads that copy's `config.toml` via `config.Load`, refuses undeclared profiles and returns exactly their configured rules; without both fields it returns none.
Claude resolves this reference at settings creation, and the fake refuses a referenced profile granting rules.
`Spec.Settings`, an `adapter.Settings`, is the profile's model and effort, passed by value and to the runtime as given, empty meaning its default ([runtime settings](../adapters.md#runtime-settings)); a runtime that cannot honour one refuses it before it starts anything with an error wrapping `ErrUnsupportedSetting`, never ignoring it. `Spec.Validate` does not check them: what is honoured is each runtime's.
`SessionSpec` is what a runtime gets for one interactive [Director session](../director.md#start): absolute session directory, copy and role prompt, a one-line first message, model and effort; `Validate` refuses anything else, and `SessionEnv` sets `CopyEnv`, `GUILDHALL_COPY`, to the copy before the spec's own entries.
`FakeName` and `ClaudeName` are the one spelling of the runtime adapter names, which [`runtimes`](adapter-runtimes.md) is keyed by and `interp.FakeAdapter` and `interp.ClaudeAdapter` refer to.
The cancel marker is the `.cancelled` sidecar beside the result file, naming the attempt: `Cancelled` reports it, refusing one that names another attempt with `ErrIdentityMismatch`, and `MarkCancelled` writes it durably and idempotently; while it is present `ReadResult` and `WriteResult` refuse with `ErrAttemptCancelled`.
The [usage file](../adapters.md#usage-file) ([attempt spend](../decisions/0079-attempt-spend.md)): `Usage` with its `Measure`s `Measured`, `Estimated` and `Unknown`, `UnknownUsage`, and `Validate`, which refuses another measure, a negative or non-finite number and a number an unknown measure gives; `UsageFile` is `usage.json` beside the result file; `WriteUsage` validates and replaces it atomically; `ReadUsage` reads a missing file as `UnknownUsage` and refuses another schema, a newer version, an unknown field or an invalid usage with `ErrMalformedUsage`.
The terminal boundary `TabHost` operates only on tabs the host created or adopted and honours its context; `AdoptTab` accepts a tab an earlier host on the same terminal created, as a durable record names it, after checking it is still there in the host's session and workspace; `Workspaces` and `CreateWorkspace` list and create the session's workspaces, which carry no ownership, a created one listed from then on and accepting tabs; `HerdrTabs` implements it over the Herdr client.
`EnsureWorkspace` returns the first workspace with a label, creating one without focus when there is none, which the [Director's tab](../director.md#the-directors-tab) is opened in.
`TabLauncher.Open` creates a tab and waits for its shell's prompt, returning the shell's name, and `TabLauncher.Type` types an argv into it quoted for that shell, so a caller can name the tab in the argv it types; `Start` is the two together.
`HerdrTabs.TypeRecorded` types one line into a recorded tab through that boundary, refusing with `ErrShellIdle` while the pane's shell is idle, which the [Director's wake](../messaging.md#waking-the-director) uses.
The native worker boundary `nativeWorker` stops one verified process and proves its exit, is idempotent and concurrency-safe, refuses an ended context without terminating, and never uses a released handle; it exists only on Windows, and other hosts refuse with `ErrStopUnsupported`.
