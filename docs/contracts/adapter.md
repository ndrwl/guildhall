# `internal/adapter`

## Contract

The spec, identity, capabilities and versioned result file, completion only from that file (`docs/adapters.md`).
`Spec.Copy` and `Spec.Profile` reference the Director's profile ([Artisan permissions](../adapters.md#artisan-permissions)); no rule list is transported.
`ProfileTools` loads that copy's `config.toml` via `config.Load`, refuses undeclared profiles and returns exactly their configured rules; without both fields it returns none.
Claude resolves this reference at settings creation, and the fake refuses a referenced profile granting rules.
`Spec.Settings`, an `adapter.Settings`, is the profile's model and effort, passed by value and to the runtime as given, empty meaning its default ([runtime settings](../adapters.md#runtime-settings)); a runtime that cannot honour one refuses it before it starts anything with an error wrapping `ErrUnsupportedSetting`, never ignoring it.
`Spec.Validate` does not check them: what is honoured is each runtime's.
`SessionSpec` is what a runtime gets for one interactive [Director session](../director.md#start): absolute session directory, copy and role prompt, a one-line first message, model and effort; `Validate` refuses anything else, and `SessionEnv` is the spec's own entries, none naming the copy.
The session directory lies under the copy, so the session's commands find it by [copy discovery](../running.md#copies); `adapter.Under` is that rule, which the conformance kits assert.
`FakeName` and `ClaudeName` are the one spelling of the runtime adapter names, which [`runtimes`](adapter-runtimes.md) is keyed by and `interp.FakeAdapter` and `interp.ClaudeAdapter` refer to.
The cancel marker is the `.cancelled` sidecar beside the result file, naming the attempt: `Cancelled` reports it, refusing one that names another attempt with `ErrIdentityMismatch`, and `MarkCancelled` writes it durably and idempotently; while it is present `ReadResult` and `WriteResult` refuse with `ErrAttemptCancelled`.
The [usage file](../adapters.md#usage-file) ([attempt spend](../decisions/0079-attempt-spend.md)): `Usage` with its `Measure`s `Measured`, `Estimated` and `Unknown`, `UnknownUsage`, and `Validate`, which refuses another measure, a negative or non-finite number and a number an unknown measure gives; `UsageFile` is `usage.json` beside the result file; `WriteUsage` validates and replaces it atomically; `ReadUsage` reads a missing file as `UnknownUsage` and refuses another schema, a newer version, an unknown field or an invalid usage with `ErrMalformedUsage`.
The terminal boundary `TabHost` operates only on tabs the host created or adopted and honours its context; `AdoptTab` accepts a tab an earlier host on the same terminal created, as a durable record names it, after checking it is still there in the host's session and workspace; `Workspaces` and `CreateWorkspace` list and create the session's workspaces, which carry no ownership, a created one listed from then on and accepting tabs; `HerdrTabs` implements it over the Herdr client.
`HerdrTabs.CreateWorkspace` captures the starting shell's ownership from the creation response; after creating a replacement, `CreateTab` waits for the initial shell's startup to finish and closes only that freshly owned starting shell, never a shell inferred from a listed workspace.
If that cleanup fails, `CreateTab` returns the replacement reference and an error naming both tabs, without typing input; that host does not retry starting-shell cleanup on later tab creations.
`IdleTabCloser.CloseTab` revalidates an owned or adopted tab and the recorded pane's membership in it, refuses moved panes, multiple panes or a non-idle shell, and closes presentation only; the caller must prove the recorded session stopped separately.
`IdleWorkspaceCloser.CloseWorkspace` closes an owned or adopted tab's whole Herdr workspace only after revalidating, immediately before the close, that the tab is in the host's session, the Herdr workspace is listed with one of the given attempt labels, it holds exactly that tab with the given label and one pane, the pane is still the recorded one and its shell is idle; `CloseLabelledTab` is `CloseTab` that also matches the tab's label.
A mismatch is a `LeftOpenError` naming what differs (`IsLeftOpen` also matches `herdr.ErrMoved`), and a Herdr workspace, tab or pane already gone is not found (`herdr.IsNotFound`); neither closer writes a task, attempt or session record, and the caller must prove the attempt finished and its launcher gone.
`workspace_close_test.go` covers both closers over the stub Herdr: each attempt label, and refusals for another Herdr workspace or tab label, session, extra tab or pane, moved pane, busy shell, unadopted record and a gone Herdr workspace.
`EnsureWorkspace` returns the first workspace with a label, creating one without focus when there is none, which the [Director's tab](../director.md#the-directors-tab) is opened in.
`TabLauncher.Open` creates a tab and waits for its shell's prompt, returning the shell's name, and `TabLauncher.Type` types an argv into it quoted for that shell, so a caller can name the tab in the argv it types; `Start` is the two together.
`HerdrTabs.TypeRecorded` types one line into a recorded tab through that boundary, refusing with `ErrShellIdle` while the pane's shell is idle, which the [Director's wake](../messaging.md#waking-the-director) uses.
The native worker boundary `nativeWorker` stops one verified process and proves its exit, is idempotent and concurrency-safe, refuses an ended context without terminating, and never uses a released handle; it exists only on Windows, and other hosts refuse with `ErrStopUnsupported`.

## Tests

Result-wait polling and timeout behavior use `testing/synctest`; the missing-result goroutine is observed blocked before publishing its result.
Real-process completion still uses generous ceilings and the shared cancellation case no longer requires a worker to initialize within 300 milliseconds ([timing policy](../test-timing.md)).

`TestNewWorkspaceReplacesOnlyItsOwnedStartingShell` crosses the real subprocess boundary with the existing Herdr stand-in and was written red first ([captured run](../evidence/director-tabs-2026-10-23-red.txt)).
`TestIdleTabCloseRefusesUnsafeIdentity` covers unowned, busy, split, moved-tab, moved-pane and cancelled cleanup; the moved-pane regression and the initial-shell-startup wait were added red first in self-review (same captured run).
`tabcontract.TestIdleClose` runs shared idle, busy, transient-busy, cancelled, mismatched-identity and already-closed cases against `HerdrTabs` and the CLI's `directorTabs` double through `TestHerdrIdleTabCloseContract` and `TestDirectorIdleTabCloseContract`.
The workspace listing contract compares workspace identity without creation-only tab ownership and allows the owned starting-shell close, but no typed input.

The workspace cases of the shared contract test (`testWorkspaces`, run against `HerdrTabs`, `fakeTabs` and `ShellPanes`) and `TestTabLauncherOpensThenTypes` were written red first against stubs ([red run](../evidence/director-tab-2026-10-22-red.txt)).
`TestSpecValidate`'s original allowed-tool cases were written red first ([red run](../evidence/artisan-allow-rules-2026-10-22-red.txt)); it now checks that a copy/profile reference is accepted without resolving its grant; `result_test.go`, `launch_test.go`, `run_test.go`; `tabhost_test.go` (shared contract test, `HerdrTabs` over a stub Herdr process and `fakeTabs`); `native_test.go` and `native_windows_test.go` (shared contract test, real Windows handle and `fakeNative`); `owned_test.go`, `owned_contract_test.go`, `cancel_test.go`; `Cancelled` and `MarkCancelled` wrap the existing sidecar functions and are exercised by the [launch tests](launch.md#tests); `conformance_test.go` (scripted runtime double, with bare prompts and on interpreter-rendered attempts mapped through `interp.Spec.AdapterSpec`); `export_test.go` exposes the `TabHost` contract test as `RunTabHostContract`, with the recorded-tab cases, which `shellpanes_unix_test.go` runs against `adaptertest.ShellPanes`; the recorded-tab cases (adopting from a second host on the same terminal, refused adoptions sending nothing, an ended context, and typing into a running or idle recorded pane) were written red first against stubs on all three hosts ([red run](../evidence/director-wake-2026-10-22-red.txt))
`usage_test.go` was written red first against stub bodies ([red run](../evidence/attempt-spend-2026-10-22-red.txt)): the file beside the result, round trips of measured, estimated and unknown usage under the versioned schema, a missing file read as unknown, each refused guess and invalid number, and each malformed file.
