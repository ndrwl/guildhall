# `internal/cli`

## Contract

Commands, output and exit codes (README); doctor's process boundary, `App.LookPath` and `App.Output`: a missing tool is `exec.ErrNotFound`, output is stdout and stderr combined, a failing command is an error with its output, and context cancellation stops a hung command; see D6 for doctor's timeout policy.
The `store`, `messages`, `task`, `decide`, `workflow approve` / `workflow approvals` and `steward rollout` commands, including the read-only task inspection reads `task timeline` (with findings and rulings) and `task files`, `task finding rule` and `task review --full` (`docs/store.md`, `docs/messaging.md`, `docs/tasks.md`, `docs/decisions-cli.md`, `docs/configuration.md`, `docs/steward.md`); task acceptance refuses undeclared profiles in the effective workflow before opening or writing the store, and refuses an unauthorized effective workflow through `workflow.Authority.Admit` over the shipped definitions and the store's approvals before writing; `workflow approve --config --repo` approves a repository's effective workflow; see `docs/tasks.md` for task acceptance and retry contracts.

`artisan start` without `--herdr-session`, `artisan stop`, `artisan status` and `artisan resume` are [owned attempt commands](../artisan.md#commands) over [`internal/launch`](launch.md); `artisan start` with `--herdr-session` is the [tab mode](../adapters.md#running-an-attempt).
The `artisan` verbs follow the [role grammar](../decisions/0053-cli-role-grammar.md): help lists every one, and `artisan run`, the pre-release name of `start`, is a usage error that names `artisan start`; their repository flag is `--repo`, and the pre-release `--repository` is a usage error that names `--repo`.
`artisan harness inventory|kill-owned|probe --lab` is the lab's [test tooling](../artisan.md#harness), refused without `--lab`.
`fake-artisan` is `fake.Main` and `claude-artisan` is `claude.Main`; `artisan start` builds its command from [`runtimes.Lookup`](adapter-runtimes.md) and refuses an `--adapter` that `runtimes.Names` does not list with a usage error naming it and the list; owned it takes `fake` or `claude`, and tab mode only `fake`.

`task start`, `step done` and `step retry` ([running a task](../running.md)) run one `interp.Engine` advance over `storeRecords`, the Director config and the state directory, under the task's lock, launching through `launch.Process`, given the copy when the advance runs from one so each launcher advances its task ([the watcher](../running.md#the-watcher)), writing what the task waits for to `next.json` beside the lock, with `Engine.StallInterval` from `config.StallInterval`, also passed to `launch.Process` so each launcher sends `worker-stalled` from its heartbeat through the store and the wake, and `Engine.ChecksRefresh` from `config.ChecksRefresh`, publishing and merging through `App.Forge`, which is `forge.GitHub` when nil, and making each task's working directory a worktree through `App.Workspaces`, which is `git.Program` when nil, with `Engine.Base` the task's base from `git.Program.Base` over the repository's configured `path` and branch `guildhall/<task>` and `Engine.Rebases` `git.Program` over the same `path`, whatever `App.Workspaces` is, on a context an interrupt cancels, so an interrupted advance returns and releases the task lock; `task start`, `step done` and `step retry` refuse a repository the config does not list (`config.ListedRepository`) before anything else, as `step finish` does before it reads its outputs, and the advance starts every attempt under `Engine.Caps` from `config.GuardRails` ([guard rails](../director.md#guard-rails)); `task new` and `workflow approve --repo` find the repository the same way, and `messages send` checks the envelope's repository against the copy's config or `--config`; `step done` refuses a result path other than the attempt's own and a result `adapter.ReadResult` refuses before calling the engine; `step retry` feeds `attempt-retried` with its `--reason`.
`step finish` ([running a task](../running.md#step-finish)) is the Director's verb for a [Director stage](../interpreter.md#director-stages): it refuses a step the repository's effective workflow does not run by the `director`, an output port its kind does not declare, an attempt that is not the step's latest, already finished or not `interp.HandedToDirector`, then, under the task's lock, copies each output into the working directory as `<port><ext>`, writes the result with `adapter.WriteResult` and feeds `attempt-result`; the prompter renders a Director stage with `roles/director.md` or the config's `[director] role`.
`storeRecords` is the production `interp.Records` and `interp.Outbox`: it opens the store for each record operation, waiting at most 30 seconds for its lock, joins each result with the close error, and satisfies `interptest.RunRecordsContract` and, through its `Send`, `messagingtest.RunMailboxContract` ([seams](../interpreter.md#seams)).

`director status --json` is the Director's [status feed](../director.md#status): one `store.DirectorView` read with the store opened read-only and the advance's 30-second lock wait, each task's `next.json` copied as written, every running attempt classified with `launch.Classify`, and `needs_me` built from those in its documented order with the command for each item, an `advance` item first for a finished attempt the task's `next.json` still waits on, or for a Director stage's unfinished attempt with a published result, naming its `step done`; the session is the newest `DirectorSession` from the same view, or `no session`, with `guard_rails`: the config's `GuardRails` when the copy, or `--config`, has a config, and the view's attempt usage on `App.Now`'s clock; the mode `standalone` until managed mode exists; and `quality`, the same config's `config.Quality`, absent with no config or when `guard_rails` reports a `config_error`.
`director status` gives each task its `spend`, a `store.SpendTotal` of its attempts by `AddAttempt` from `NoSpend`, and `guard_rails.spend_today`, the view's `AttemptUsage.Spend` ([spend](../director.md#spend)).
`director status` lists a `recovering` newest session first in `needs_me`, naming `guildhall director ready`.
`director start [runtime] [--check]` is the [session supervisor](../director.md#start): over a copy, a preflight of the config's admission (a managed copy refused naming `director enrol`), the runtime from [`runtimes.LookupSession`](adapter-runtimes.md) and its program on `PATH` through `App.LookPath`, the store and `App.InstallSkills`/`App.InstallBaseline`, one doctor-style line each, then an `artisans` line naming the profiles that run the claude adapter, which refuses nothing, any refusal exit 1 recording nothing; then `StartDirectorSession` as `recovering` with `artisan.Self`, `render.Session` into `<copy>/director/session-<n>/` with the `needs_me` snapshot, each item with its command but a `checks` item, which names the session supervisor instead, the runtime's session command as a child on `App.Stdin`, `App.Stdout` and `App.Stderr`, and the session recorded `stopped` once it ends, exit 1 for a nonzero runtime status.
From before the session is recorded until it is recorded `stopped` the supervisor handles the interrupt, and on Unix hangup and termination, which it passes on to the runtime as a termination; one received before the runtime starts starts none, and either way the session is recorded `stopped` with exit 1.
`director start`, in either mode, refuses with exit 1 naming `director: live`, while the newest session is not `stopped` and `artisan.Probe` does not show its supervisor `Gone`; the supervisor checks inside the transaction that records the new session, and records the `--herdr-session`, `--herdr-workspace`, `--herdr-tab` and `--herdr-pane` binding it is given, all four together and never with `--tab`.
`director start --tab` is the [tab wrapper](../director.md#the-directors-tab): the same preflight, then a `herdr` line for the config's `HerdrSession` opened through `App.DirectorTabs` (nil is `HerdrTabs` over `herdr` on `PATH` after `Status`), then `adapter.EnsureWorkspace` labelled with the Director's name, `TabLauncher.Open` of a tab labelled `director <name>` and `TabLauncher.Type` of the supervisor's argv with its pane binding; it waits for a session after the newest it read that records the pane, fails once the pane's shell is idle again after it was seen busy and after two minutes, and prints the session as JSON; it never closes the tab.
`director ready` moves a `recovering` newest session to `running` and prints it; while it is `recovering`, `task new` and `task start` of a task with no attempt are refused naming `director ready`.
`director pause` and `director resume` move a live newest session between `running` and `paused` with `SetDirectorState`, refusing no session, `recovering`, `stopping`, `stopped` and a supervisor `artisan.Probe` proves gone; `resume` prints `{"session":...,"needs_me":[...]}` with the status feed's `needs_me` and, when it moved the session, `"wake"`, the outcome of `messaging.WakeResumed` over the store and `App.DirectorPane` for the feed's items by kind, bounded by `wakeTimeout`, a failed wake reported on stderr without failing the resume.
While the newest session is `paused` or `stopping`, `task start` without `--decision` and `step retry` print `{"wait":"paused"}` and record nothing, and every advance sets `Engine.Hold` so `step done` and `task start --decision` start no next attempt; `needs_me` lists an open task whose `next.json` waits `paused`.
`director stop [--now]` records `RequestDirectorStop`, or `EndDirectorSession` with `superseded` when `artisan.Probe` proves the supervisor gone, then runs `launch.Stop` on every attempt with no outcome, exit 1 if one is not proven stopped; the supervisor reads its session every `App.SessionPoll` (1 s when zero) while the runtime runs and ends it at the end of the turn, `App.StopGrace` (60 s when zero) standing in for a turn end as below, or at once for `stop_now`, then records `stopped` and exits 0.
`director handoff --note-file <path|->` reads the note with `readText`, the decision answer's rules, refuses a blank note or one over `store.MaxHandoffNoteBytes`, and records it with `RecordHandoffNote` for the newest session, writing it with `atomicfile.Write` under `<state>/documents`; `director reload [--now]` records `RequestDirectorReload`, `--now` refused without a live newest session, without a note from it, or while a Director stage attempt (`interp.HandedToDirector`) that started after the note runs.
`director turn-started` and `director turn-ended` signal the newest session's [`session`](session.md) endpoint under `<copy>/director/session-<n>/` and is exit 1, never 2, for any failure, including a usage error.
The supervisor binds that endpoint for each session, renders `startup.md` with the newest note's path, decides with `decideEnd` at each turn signal and each poll, idle while the newest turn signal is a turn end with no wake since or, with a hook, once no turn signal or wake has arrived for `[director] idle_after` by `App.Now`, the stop and reload `--now` at the turn end or after `App.StopGrace` without a hook or when idle, a plain reload at a quiet point, reading the running Director stages only for a plain reload it would otherwise apply, and on a reload records the session `stopped` as `reloaded`, or `stopped` as for a stop with no new session when a stop arrived while the runtime was ending, re-admits the config, resolves the runtime again, ending with exit 1 if it is refused, and starts the next session, which records the pending reload applied; a runtime that ends by itself is recorded `stopped` and a requested reload is left for the next `director start`.
The status feed's session carries `DirectorView.Handoff` as `handoff_note` and `DirectorView.Reload` as `reload`.
The supervisor's tick also ticks its `checksWatch`, which every `ChecksRefresh` of the session's config, one round at a time, advances in this process, as `task start` does with the App's forge and workspaces, each open task whose `next.json` waits `checks` while the newest session is `recovering` or `running`, appending failures and the advance's output to the session directory's `checks.log`; the supervisor waits for a running round before recording the session `stopped`.
`needs_me` lists such a task as a `checks` item, after `paused` ([checks](../director.md#checks)).
`fake-director` is `fake.DirectorMain`.
Every send to the Director, by `messages send` and by a launcher's outbox (`wakingOutbox`), then runs `messaging.Wake` over the store file opened per call and `App.DirectorPane`, Herdr's `herdr` on `PATH` when nil, bounded by `wakeTimeout`; a failed wake never fails the send.
The engine's outbox in an advance (`deferredOutbox`) records its sends under the task lock and keeps the ids sent to the Director, and the advance wakes each, in send order, after releasing the lock, whether or not it succeeded ([waking the Director](../messaging.md#waking-the-director)).

`render <request.json>` reads one JSON rendering request with [`strictjson`](strictjson.md); decoding refusals are usage errors (exit code 2) before installation or rendering.
It invokes `App.InstallSkills` to install a temporary first root named `release` before optional managed and Director roots.
Before installing or rendering, it validates the step settings through `workflow.ValidateStepSettings`, rejecting malformed values, invalid or duplicate names, disallowed actors and unknown setting keys with exit code 2.
It returns the prompt manifest as JSON, retains the rendered attempt, removes the temporary root, and refuses to replace an existing attempt.
A request without a baseline role or guide path takes it from `App.InstallBaseline`'s temporary release baseline.
`cmd/guildhall` supplies the embedded release skills and baseline installers; an unconfigured installer is an error, in `render` and in every advance.
