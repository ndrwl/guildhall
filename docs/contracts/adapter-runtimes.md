# `internal/adapter/runtimes`

## Contract

The one owner of the runtimes Guildhall can launch ([running an attempt](../adapters.md#running-an-attempt)).
`Names` lists them in sorted order, `claude`, `codex` and `fake`; `Lookup` returns the runtime called a name, its commands running the given guildhall executable, and refuses any other name, including the interpreter's test-only `mock`, with an error wrapping `ErrUnknown` that names it and lists `Names`.
It is keyed by `adapter.FakeName`, `adapter.ClaudeName` and `adapter.CodexName`, the names' one spelling, which `interp.FakeAdapter`, `interp.ClaudeAdapter` and `interp.CodexAdapter` also refer to.
The registry is split: `claude` and `fake` run attempts and Director sessions, and `codex` runs attempts only ([read-only steps](../adapters.md#running-an-attempt)); `SessionNames` lists the session runtimes, `claude` and `fake`.
`Runtime` is the consumer's narrow view of an adapter: its attempt command, refused with no command for an invalid spec, and `CheckSettings`, which refuses a model or effort the runtime cannot honour with an error wrapping `adapter.ErrUnsupportedSetting`, honours the zero `adapter.Settings` and starts nothing, so a preflight runs it before any attempt is recorded; `Command` refuses what it refuses.
It also declares what the runtime can do, so no caller compares runtime names: `GrantsTools`, whether it applies a profile's `allowed_tools` and repository grants, only `claude`; `SkillPolicy`, whether it applies a Claude skill policy, only `claude`; and `Signin`, its `adapter.Signin` entry, which [`guildhall signin`](../signin.md) lists in name order before `gh`, the zero entry for `fake`, the guildhall executable.
The first two agree with the runtime's `adapter.Declared` entry, which `config`, `grant` and `quality` read since they cannot import this package.
A new runtime is added here, with its name and declaration in package `adapter`, and nowhere else.
`Session` is a `Runtime` that also runs Director sessions; `SessionOptions` returns it with the copy's resolved Director skill policy and task-page `adapter.Links` applied where it takes them, a nil argument leaving that option as it was, so the supervisor needs no type assertion; `fake` ignores both.
It is the supervisor's narrow view of a runtime's Director session: the program it needs on `PATH` (none for the fake, which is the guildhall executable), its skills directory, its own session files, its session command, whether it has turn hooks signalling each turn's start and end, `TurnEndHook`, and whether it supplies context use for [automatic handoff](../director.md#automatic-handoff), `ContextReport`, an optional capability; `LookupSession` returns it for every name `SessionNames` lists, refuses an attempt-only runtime, `codex`, with an error wrapping `ErrNoSession` that names it and lists `SessionNames`, and refuses any other name with an error wrapping `ErrUnknown` that lists `SessionNames`.
`PersistentSession` is the optional filesystem boundary for a runtime that needs a stable interactive folder identity: `PrepareSessionWorkspace` publishes rendered runtime files only after the previous process ends, returns the stable working directory or an error that starts no process, and never changes the numbered record or runtime-owned trust state.
The Director supervisor exercises it over Claude's real workspace and trust-gated process stub in `TestDirectorClaudeReusesTrustedWorkspace` and `TestDirectorClaudeReloadReusesTrustedWorkspace` ([red evidence](../evidence/director-trust-2026-10-23-red.txt)).
`artisan start` is the consumer, in both of its modes; `launch.Process` passes names through to it, and the interpreter's test-binary guard, `interp.CheckAdapter`, is unchanged.

## Tests

`runtimes_test.go` was written red first against stub bodies ([red run](../evidence/stall-adapter-choice-2026-10-22-red.txt)): each name builds its adapter's subcommand over the executable in the spec's working directory, with no command for an invalid spec, and unknown names are refused by name with the list.
`TestEachRuntimeChecksSettings` was written red first ([red run](../evidence/profile-model-effort-2026-10-23-red.txt)): every runtime honours the defaults and its `Command` refuses what its `CheckSettings` refuses, and Claude refuses an effort Claude Code does not take, naming it.
`TestLookupSessionConstructsEachRuntime` pins `LookupSession` the same way; it was added with the implementation and was not run red.
With `codex` registered, the tests list three names, use `gemini` as the unknown name, and check that `LookupSession` refuses `codex` with `ErrNoSession`; `internal/adapter/codex`'s `codex_test.go` pins its command line and settings refusals.
These were written with the change and not run red.
`TestEachRuntimeDeclaresItsCapabilities` is the registry test: for every name in `Names`, `GrantsTools`, `SkillPolicy` and `Signin` have the expected values, the sign-in entry is complete or, for `fake` only, zero, the `adapter.Declared` entry exists and agrees, and every session runtime takes `SessionOptions`; it could not compile before the capabilities existed. `TestClaudeSessionOptions` pins that the Claude session renders the links it is given, keeps them across a nil argument and stays a `PersistentSession`.
