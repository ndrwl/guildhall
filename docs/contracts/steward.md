# `internal/steward`

## Contract

[Rollouts, verification and writer containment](../steward.md#apply); the `Copier` and `Apply` doc comments in [`rollout.go`](../../internal/steward/rollout.go) own the consumer transport and writer-lock API contracts.
`privateLock` in [`lock.go`](../../internal/steward/lock.go) is the only taker of the private lock, for `Apply`, `Collect`, the takeover's apply and abandon, the secrets `Set` and `Apply`, `Retire` and `MarkRotated`; `TakePrivateLock`, which it wraps, is exported only so `internal/cli` tests can hold a real lock. The lock is a kernel lock on `.rollout.lock` (`artisan.LockPathAt` far past the record), so the OS releases it when its owner dies. It writes a `LockOwner` record through the locked handle and refuses a held lock with a `*BusyError`, which matches `ErrBusy` and `fs.ErrExist` and names the owner, a live process; it reads an unreadable record as an unknown owner. Release truncates the record and closes the file, and nothing ever removes `.rollout.lock`: the file stays as the last owner's record and is not a lock by itself.
`MessageDropPath`, `ReceiveCommand` and `Deliver` deliver one [Steward message](../steward.md#steward-messages): `Put` to the copy's drop file, then the fixed `messages receive --copy <dir>`, whose printed `messaging.ReceiveResult` is returned and any failure is an error; `Report`, `ReportID` and `Report.Envelope` build a `steward-report` with one id per issue and copy; `CheckCommand` admits `messages receive --copy <dir>` and no other form of it.
`StatusCommand` is the read-only `director status --json --copy <dir>`, which `CheckCommand` admits in that one form, and `ParseDirectorStatus` reads a copy's `DirectorHealth` from its output, at most `MaxStatusBytes`, ignoring fields it does not read and returning `ErrNoHealth` for a feed with no `health` ([Director health](../steward.md#director-health)).
`Secrets` sets and pushes [machines' secrets](../secrets.md#the-steward-pushes-them): `SopsConfig` is `.sops.yaml` generated from the roster's `age_recipient` and `recovery_recipient`; `Set` decrypts `SecretsFile(machine)` at `HEAD` with the recovery key, adds the value, encrypts it with `secrets.Encrypt` and commits only it and `.sops.yaml` under `.rollout.lock`, then publishes; `Plan`, `WriteSecretsPlan`, `ReadSecretsPlan` and `Apply` push the committed ciphertext to `RemoteSecretsFile` with a read-back digest and `SecretsCheckCommand`, every apply needing `approve` to be the plan's digest; plans and receipts hold names and digests only. `CheckCommand` admits `secrets check --json --copy <dir>` and no other `secrets` command.
`RetirePlan`, `WriteRetirePlan`, `ReadRetirePlan` and `Retire` [retire a machine](../secrets.md#retiring-a-machine): the plan lists every name in its file as `Rotation`s, one per other machine whose file holds it or one with no machine when none does, and the revocation steps, and refuses a machine already retired; `Retire` needs `approve` to be the plan's digest and, under `.rollout.lock`, removes only the machine's `age_recipient` line, regenerates `.sops.yaml`, removes its file and writes its `RetiredFile` record, with the commit it read the file at, in one commit through `git.WorkTree.CommitChanges`, then publishes; `Set` closes an open record's rotation of its name on its machine in the same commit, unless the value is the machine's old one or the retired file's, which it decrypts with the recovery key; `MarkRotated`, under `.rollout.lock`, closes a rotation with no machine and commits and publishes the record. A record closes only when every rotation has.

`ParseProvisionRequest`, `RenderConfig`, `Setup.PlanProvision` and `Setup.ApplySetup` on a `SetupKindProvision` plan are [provisioning](../steward.md#provisioning): a plan derived from the machine's `setup doctor --json` reports, the `new-copy` preflight `StepFile` whose gaps are `ErrCopyExists`, a `StepFile` for each step file with its digest, a `fix` or `wizard` step per gap with the gap's id, Steward-written step files copied under the copy's `state/steward/setup`, then `config`, `managed`, `store`, `clone-<id>`, `adopt`, `enrol`, `reload`, `start`, `roster` and `summary`, which writes `SetupSummary` as `summary.json`; `ErrCopyExists` and `ErrWizardRecord` are its own refusals.
Takeover plans' digests are unchanged, since the provisioning fields are omitted from them.
A request with `bootstrap = true` on a machine where `sha256sum <guildhall_path>` reports no file gets a [bootstrap](../steward.md#bootstrapping-a-bare-machine) plan instead: `SetupPlan.Bootstrap` names the version, platform and the binary's and launcher's targets, copied from `Setup.Self`'s `SelfBinary`, and its steps are `guildhall-copy`, `launcher-copy` and `guildhall-install` (`HashCommand`, `InstallFromCommand`); a file there not the plan's is `ErrCopyExists`, and neither file runs unless `sha256sum` reports the plan's sha256.
`CheckCommand` takes a command's words and values as one pattern: `DoctorCommand`, `FixCommand`, `StoreInitCommand`, `AdoptCommand`, `StartTabCommand` and `CloneCommand`, whose program is `git`, are admitted in those forms only, each value checked as its placeholder says (`ValidRemote`, `SetPattern`); `LongCommand` names those an `SSH` Runner bounds with `LongTimeout`.

## Tests

`provision_test.go` drives `PlanProvision` and `ApplySetup` against a `stewardtest.Fleet` machine whose doctor answers from the real step files: `TestProvisionDryRun` (the steps and their kinds and argv, the Steward-written file and its digest, a config that loads, no change to the machine, the same digest twice), `TestProvisionDryRunRefuses` (`ErrCopyExists` for a config, store or clone, `ErrRosterConflict`, a Windows machine, a missing Herdr with no pins), `TestParseProvisionRequest`, `TestProvisionGuildhallFacts` (the `guildhall-pin`, `tailscale-ssh` and `herdr-session` gaps as wizard steps given the request's values, waiting before any copy file is written), `TestProvisionNeverCopiesOverUnreadable` (a copy target that cannot be read for a reason other than its absence fails the step and is left as it is), `TestProvisionApply` (a fix, a wizard wait for a missing, malformed, other-file and still-open record, never running the wizard, every Guildhall step once, the roster commit, the summary, and an apply of the finished plan changing nothing), `TestProvisionResume` (a failure at each acting step, before and after it acts, then a resume acting once) and `TestProvisionApplyRefuses` (`ErrPlanChanged` for a Steward-written file changed at its source or in the plan and for a changed doctor report, and `ErrCopyExists` at the clone step); `TestCheckCommand` and `RunRunnerContract` admit every provisioning command and refuse the forms around them.
`bootstrap_test.go` drives the bootstrap the same way: `TestBootstrapDryRun` (only `sha256sum` runs, the three steps, the allowed install argv, the same digest twice), `TestBootstrapApply` (both files copied and checked before the install, a re-apply copying nothing, and the next dry run planning the ordinary provisioning), `TestBootstrapNeverRunsAnotherBinary` (`ErrPlanChanged` for a file at `guildhall_path` before the first apply, left as it is, and no install once the copied binary changed) and `TestBootstrapDryRunRefuses` (no `guildhall_path`, another OS, a version that is not a release, another pin).

`messages_test.go`: `TestDeliver` copies then receives, on a Windows path, and returns delivered and refused results, and errors for a failing command, an unreadable result and an unreachable machine; `TestReportID` keeps one id per issue and copy; `ssh_test.go`'s `TestCheckCommand` and `stewardtest.RunRunnerContract` admit `messages receive --copy` and refuse its other forms.
`health_test.go`: `TestParseDirectorStatus` reads the session and health, refuses a feed with no health, output that is not JSON and an oversized feed; `TestCheckCommand` and `RunRunnerContract` admit `director status --json --copy` and refuse it without `--json`, with the flags reordered, with `--store`, with a relative copy and with an extra argument.
`secrets_test.go`: roster keys must be distinct age public keys, `SopsConfig` has one rule per machine and needs a recovery key, and `CheckCommand` admits `secrets check --json --copy` only; `internal/cli` `steward_secrets_test.go` runs set, plan, approval request and apply end to end over a round-tripping fake `sops`, finding no value in the private config, its remote, the plan or the receipt, and a plan refusing a machine whose key is not the roster's.
`retire_internal_test.go`: `withoutRecipient` removes only the age_recipient line and refuses an inline roster, and a `RetireReceipt` closes rotation by rotation, a rotation with no machine only by its mark; `internal/cli` `steward_retire_test.go` plans, approves and applies a retirement end to end, checking the plan lists every name and credential, the commit removes the recipient and file and leaves the other machine's file untouched, the record stays open through a `secrets set` of the machine's old value and of the retired machine's, and after a new value until the name only the retired machine held is marked, `--rotated` is refused in a session and for a name set anew, the record closes with the mark, a closed retirement cannot be planned again, and no value is in the private config, its remote or the plan.

`stewardtest.RunCopierContract` (shared contract test, including that only a missing source's `Fetch` error wraps `fs.ErrNotExist`) runs against the scp `Transport`, played by the test binary in a separate process (`scp_test.go`), and the in-memory `stewardtest.Fleet` that `internal/cli` tests use; `rollout_test.go`, `lock_test.go` (real files and an owner process), `lock_slowopen_linux_test.go` (Linux only, red against the base `LockPathAt`: `TestTakePrivateLockSlowOpenIsNotBusy` stalls the open of a free `.rollout.lock` past `lockWait` with [`testenv.StallOpens`](testenv.md#contract) and wants the lock, not `ErrBusy`), `roster_test.go`, `managed_test.go`
