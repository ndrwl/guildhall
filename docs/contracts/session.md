# `internal/session`

## Contract

The Director session supervisor's control endpoint ([the end of a turn](../director.md#the-end-of-a-turn), [decision](../decisions/0082-director-handoff-reload.md)).
`EndpointPath` is `supervisor.sock` in an absolute session directory, `ErrPath` for a relative directory or a path longer than `endpoint.MaxPath`.
`Listen` binds the one [endpoint](endpoint.md) there for one session number, an AF_UNIX stream socket on Windows as on Unix, removing a leftover socket nothing listens on and refusing, and keeping, one that answers (`endpoint.ErrAnswers`) or any file that is not a socket (`endpoint.ErrUnknown`); on Unix the socket is `0600`; `Close` stops it and removes the socket file, idempotently.
`Signal` sends one `guildhall.session-control/1` request line naming the session and the turn signal, `TurnStarted` (op `turn-started`) or `TurnEnded` (op `turn-ended`), and waits for the reply line; nothing listening is `ErrNoSupervisor`, an endpoint for another session `ErrMismatch` and a reply that is not the protocol `ErrProtocol`.
The endpoint decodes each request strictly, as it does for the attempt endpoint, and answers a malformed, unversioned, newer, extended or unknown request, or one for another session, with an error and no turn signal.
`Endpoint.Turns` receives the answered turn signals in order, each delivered before its reply, holding one: a signal that arrives while another is unread replaces it, so the unread value is always the newest.
The endpoint does not authenticate its peers; access control is the session directory's.

The waiter operations ([decision](../decisions/director-wake-hook.md)) share the protocol, adding the request fields `waiter`, `line`, `hold` and `due` and the reply fields `line`, `retired` and `delivered`, each omitted when empty:

- `WaitWake` (op `wait-wake`) is one long poll of a waiter id: it registers the id, retiring an older waiter, whose open and later polls and refresh are answered `retired` (`ErrRetired`), and is held for up to `PollHold` (30 seconds) until a line is handed, answered with the line, or with none so the waiter polls again. A waiter answered with a line is spent and no longer registered, since it exits to wake the Director.
- `Wake` (op `wake`) hands a counts-only line to the registered waiter, keeping it for the waiter's next poll when none is open, or for a newer waiter that replaces it first, and replacing a line not yet taken; with no waiter registered, including one that has taken a line, it is `ErrNoWaiter`. `WakeDue` adds `due`, the handoff reasons due, which the line the waiter takes ends with as `DueLine`'s suffix `; handoff due (<reasons>)`; a line that replaces one not yet taken keeps that line's reasons with its own, in first-seen order. It also adds `hold`, which a message's wake sets: while holding is on, a held wake with a waiter registered is accepted, answered `delivered` at once, and held for the supervisor's `Release`, ending no poll; with none registered it is `ErrNoWaiter`, as any wake is. With holding off, or without `hold`, a wake is handed at once.
- `Refresh` (op `refresh`) reports a waiter refreshing itself before its hook timeout.
- `Endpoint.Hand` hands a line from the supervisor itself, and `Endpoint.Waiter` reads whether a waiter is registered, not spent and a poll of it open or its last ended within `WaiterLease` (5 seconds), and the counts of lines taken and refreshes, each of which the supervisor counts as a wake. It also reads `Held`, the running count of held wakes accepted, so the supervisor sees new ones, `Pending`, set while a held wake waits for release, and `Due`, set while one of those carried a handoff reason.
- `Endpoint.SetHold` turns holding on or off; it is off until set, so an endpoint whose user never sets it hands every wake at once. `Endpoint.Release` hands its line, with the suffix of the union of the held wakes' reasons due, to the registered waiter and clears the held wakes; with none registered it hands nothing, still clears them and is `ErrNoWaiter`, and an empty line clears them and hands nothing. The held wakes are the session's, not one waiter's, so a wake held while an older waiter was registered is released to the newer one that replaced it. The endpoint keeps no clock for holding: when to release is the supervisor's.
- `Close` first answers every open poll `retired`, so it never waits out a held poll, and answers polls arriving after it the same; it drops any held wake, whose messages stay unread.

The session's context report ([automatic handoff](../director.md#automatic-handoff)) is `context.json` (`ContextFile`) in the session directory: `WriteContext` replaces it atomically with a `guildhall.session-context/1` document holding `used_percent` and `reported_at`, refusing a relative directory or a percent outside 0 to 100 and writing nothing; `ReadContext` decodes it strictly, a missing file wrapping `fs.ErrNotExist`.
`NumberEnv`, `GUILDHALL_SESSION`, is the session number the supervisor sets in the runtime's environment, so the reporter finds its directory without the store.

## Tests

`session_test.go` was written red first against stub bodies ([red run](../evidence/director-handoff-2026-10-22-red.txt)): the path rule and its refusals; a child process, the test binary playing the end-of-turn hook, signalling the supervisor across a real process boundary, a signal for another session refused and not received, and two unread signals coalescing; `TestTurnStartSignalsTheSupervisor`, added with the turn-start signal and not run red, has a child process signal a turn start, refused for another session, and sees the newer of two unread signals replace the older in either order; no supervisor before binding and after `Close`, which removes the socket; binding over a stale socket, refusing a live endpoint without disturbing it and a regular file, which is kept; and malformed requests answered with an error and never received.
The regular-file case was red against the first implementation, because a dial to a regular file on Linux is refused like a stale socket; the stale-file rule now checks the file is a socket first.
`TestEndpointContract` runs the shared [`endpointtest.RunEndpointContract`](endpoint-endpointtest.md) over the session endpoint, the owner being the session number; it was added when the session endpoint was composed over `internal/endpoint` (sustainability review 12, F43), and `TestListenOverLeftovers` now names `endpoint.ErrAnswers` and `endpoint.ErrUnknown` for its refusals.
`waiter_test.go` was added with the waiter operations and not run red: a wake handed to a registered waiter's poll, and `ErrNoWaiter` with none; a newer waiter retiring the older's poll and refresh; a line handed between polls kept for the next, a refresh counted, and a waiter that stopped polling unregistered after the lease; and an open poll answered at `Close`, `ErrNoSupervisor` while nothing listens, and the same waiter woken once an endpoint listens again.
`TestASecondWakeAfterTheWaiterTookOneIsNoWaiter` was added after build review found a second wake within the lease handed to a waiter that had already taken a line, recorded `woke` and dropped when the next waiter registered; it failed against that code: the second wake is now `ErrNoWaiter` and the next waiter is handed only the catch-up wake. `TestALineAnOlderWaiterDidNotTakeReachesTheNewer` covers a line handed between polls reaching the waiter that replaces its holder.
The held-wake tests were added with d20: `TestAHeldWakeDoesNotEndAnOpenPoll`, `TestReleaseHandsTheLineWithTheMergedDues`, `TestAHeldWakeWithNoWaiterIsNotDelivered`, `TestAHeldWakeIsReleasedToTheNewerWaiter`, `TestReleaseWithNoWaiterClearsTheHold`, `TestHoldOffHandsAHeldWakeAtOnce` and `TestAReplacingLineKeepsTheUntakenDues`. They call `WakeDue`, `SetHold` and `Release`, which the code before d20 lacks, so they could not be run red against it; `TestAReplacingLineKeepsTheUntakenDues` was run red against `hand` with its replacing rule as before d20, a replacing line keeping only its own reasons, and failed with the untaken line's `context 72%` dropped. The existing waiter tests pass unchanged. The supervisor's side is tested in `internal/cli/director_waiter_test.go` over a fake waiter and a moved clock, with no sleeps: a burst released once after `wake_quiet` with the store's counts at release, a release at `wake_max_delay` under steady wakes, no release with `wake_quiet` `0s`, a release finding no waiter becoming a missed wake with the notice and one catch-up line, a pending hold keeping a reload waiting (run red with the pending hold not counted against `Idle`: the reload applied at once), and a hold with nothing left to report cleared without a wake.
`context_test.go` was written red first against stub bodies ([red run](../evidence/director-handoff-triggers-2026-10-22-red.txt)): reports written and read back whole, each replacing the last, naming the schema; `TestContextReportRefusals`, a percent out of range or a relative directory writing nothing and a malformed, unversioned, newer, extended or out-of-range report refused, passed against the stubs, which refuse everything.
