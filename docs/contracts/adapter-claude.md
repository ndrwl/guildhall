# `internal/adapter/claude`

## Contract

The minimal Claude Code runtime ([Claude adapter](../adapters.md#claude-adapter)): no optional capabilities; `Adapter.Command` is `guildhall claude-artisan` for a valid spec in its working directory and environment, refusing an invalid spec or an unset executable with no command.
`Run` is the wrapper: it refuses a cancelled attempt (`adapter.ErrAttemptCancelled`) or an existing result (`adapter.ErrResultExists`) without starting Claude, replaces the model directory (`ModelDir`, `artisan.ModelDir` beside the result) with the prompt copy (`PromptCopy`) and the `inputs` and `skills` beside the prompt, runs `claude` (`PATH`, or an absolute `--claude`) with `ClaudeArgs` and no standard input, and once Claude exits publishes the draft's bytes at the result file by hard link, never replacing one and never after the cancel marker; no draft is `ErrNoDraft`.
The cancel marker, an interrupt or the end of its context stops Claude (interrupt on Unix, termination on Windows, a kill after `StopGrace`) and publishes nothing; the marker is not an error.
`Adapter.Session` is the interactive [Director session](../director.md#start): `claude --append-system-prompt-file <role> --add-dir <copy> [--model <model>] [--effort <level>] -- <first message>` in the session directory with the session environment, `Program` on `PATH` or an absolute `Claude`, both settings passed only when nonempty, and no command for an invalid spec or settings `CheckSettings` refuses; its skills directory is `.claude/skills` and `SessionFiles` is `Settings` at `.claude/settings.json`, allowing `guildhall`, read-only `git` and `git remote -v` with no further arguments in Bash, denying direct `guildhall claude-artisan`, `guildhall fake-artisan`, `guildhall fake-director` and `guildhall artisan start` calls with or without arguments via `Bash(<command>:*)` rules that override the broad `guildhall` allow, preserving task orchestration and `artisan stop/status/resume`, denying any `git` command with `--output` (`git diff --output=<file>` writes a file), denying edits to the copy's `config.toml` and `managed.toml` by absolute rule paths, a Windows drive written `//c/...`, and registering `TurnStartCommand`, `guildhall director turn-started` with no path, as the `UserPromptSubmit` hook and `TurnEndCommand`, `guildhall director turn-ended` with no path, as the `Stop` and `StopFailure` hooks, so `TurnEndHook` is true, and `ContextReportCommand`, `guildhall director context-report`, as the `statusLine` command, so `ContextReport` is true.
`ParseStatusLine` reads `context_window.used_percentage` from the JSON Claude Code passes a status-line command, rounded to a whole percent and clamped to 0 to 100, reports none without an error when it is absent or null, as before the first message, and refuses input that is not one JSON object ([automatic handoff](../director.md#automatic-handoff)).
`Adapter.Command` passes `Spec.Copy` and `Spec.Profile` as `--copy` and `--profile` before any `--claude`; `ParseArgs` reads the reference, never rules.
`CheckSettings` enforces the Claude [runtime settings](../adapters.md#runtime-settings), with supported efforts declared by `Efforts`, and refuses unsupported values with `adapter.ErrUnsupportedSetting` naming the setting; it does not check that a model exists.
`Command`, `ParseArgs` and `Run` refuse what it refuses, `Command` returning no command; `Command` passes `Spec.Settings` as `--model` and `--effort` after the profile reference and before any `--claude`, `ParseArgs` reads them into `Args.Settings`, and `ClaudeArgs` passes them to Claude Code after `--permission-mode`, each only when set.
`--allow-tool` is a usage error.
`Run` resolves the reference through `adapter.ProfileTools` and materialises exactly the loaded profile's rules, refusing an undeclared profile; without both reference fields it grants nothing.
`TestDirectorCannotPassGrantRules` reproduced the bypass before this fix ([red run](../evidence/artisan-grant-reference-red.txt)); `TestWrapperProfileAuthority` covers empty, undeclared and incomplete references over the stub.
With allowed tools, `Run` writes `ArtisanSettings`, `{"permissions":{"allow":[<rules>]}}` and a newline, at `ArtisanSettingsPath`, `ArtisanSettingsFile` (`claude-settings.json`) beside the result file and outside the model directory, before starting Claude; with none it writes nothing.
`ClaudeArgs` is print mode with `Instruction`, `OutputFormat` (`json`), `PermissionMode` (`acceptEdits`), `--settings` with `ArtisanSettingsPath` when the attempt has allowed tools, and only the model directory added; `Instruction` names the prompt copy and the draft (`DraftFile`, in the model directory) on their own lines and gives the result object for the attempt's identity.
`ParseUsage` reads Claude Code's JSON result message as an `adapter.Usage`: its `usage` tokens measured, its `total_cost_usd` an estimated cost, what it lacks unknown, and output that is not one JSON object or gives an invalid number an error; once Claude exits, unless it was stopped, `Run` writes that usage as the attempt's [usage file](../adapters.md#usage-file), unknown when the output gives none, before publishing the draft (a failure to write it is returned as an error after the draft is still published), and writes the message's `result` text to its stdout, or the output unchanged when it is not a result message, keeping at most 4 MiB of it.
`Denials` reads the result message's `permission_denials` as each denied tool with its command or file, such as `Bash(go test ./...)`, or the tool alone, and none for output that is not a result message; `Run` names them on its stderr ([Artisan permissions](../adapters.md#artisan-permissions)).
`ParseArgs` refuses a prompt inside the model directory; it and `Main` follow the fake's shape: exit 0, 1 on failure, 2 on refused arguments.

## Tests

`TestSessionCommand`'s explicit `--effort high` expectation was run red before the effort-default implementation; direct session model/effort refusals were added afterward.

`TestSessionCommand`'s delimiter expectations failed before the startup fix with and without a model, and pass afterward.
The shared `TestClaudeSessionContract` executes the no-model session against the strict stub, so an unseparated first message now fails at the process boundary.
`TestSessionStubRequiresMessageSeparator` independently exercises both accepted and refused argv shapes ([decision and evidence](../decisions/director-startup-admission.md)).

`claude_test.go` was written red first against stub bodies ([red run](../evidence/claude-adapter-2026-10-21-red.txt)), every test failing: `adaptertest.RunConformance` as a direct child, on interpreter-rendered attempts and inside the Artisan launcher on this platform's unit, where a stop must end at rung 1; the command and argument parsing; `ClaudeArgs` and `Instruction`; refusals that start nothing; a stale draft never published; and a stop on the context's end.
`settings_test.go` was written red first against stub bodies ([red run](../evidence/profile-model-effort-2026-10-23-red.txt)): `TestSettingsReachClaude` (the wrapper argv, its round trip through `ParseArgs` and `ClaudeArgs`, and neither flag for unset settings), `TestSettingsReachTheStub` (the stub Claude Code run by `Run` records exactly the settings it was given) and `TestClaudeRefusesSettingsItCannotHonour`; `TestParseArgsRefuses`'s unknown-flag case moved from `--model`, now a wrapper flag, to `--temperature`.
