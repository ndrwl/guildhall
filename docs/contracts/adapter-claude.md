# `internal/adapter/claude`

## Contract

The minimal Claude Code runtime ([Claude adapter](../adapters.md#claude-adapter)): no optional capabilities; `Adapter.Command` is `guildhall claude-artisan` for a valid spec in its working directory and environment, refusing an invalid spec or an unset executable with no command.
`Run` is the wrapper: it refuses a cancelled attempt (`adapter.ErrAttemptCancelled`) or an existing result (`adapter.ErrResultExists`) without starting Claude, replaces the model directory (`ModelDir`, `artisan.ModelDir` beside the result) with the prompt copy (`PromptCopy`) and the `inputs` and `skills` beside the prompt, runs `claude` (`PATH`, or an absolute `--claude`) with `ClaudeArgs` and no standard input, and once Claude exits publishes the draft's bytes at the result file by hard link, never replacing one and never after the cancel marker; no draft is `ErrNoDraft`.
The cancel marker, an interrupt or the end of its context stops Claude (interrupt on Unix, termination on Windows, a kill after `StopGrace`) and publishes nothing; the marker is not an error.
`Adapter.Session` is the interactive [Director session](../director.md#start): `claude --append-system-prompt-file <role> --add-dir <copy> --settings <session settings> --plugin-dir <absolute bundled Lanterns directory> [--model <model>] [--effort <level>] -- <first message>` in `SessionSpec.Dir` with the session environment, `Program` on `PATH` or an absolute `Claude`, both settings passed only when nonempty, and no command for an invalid spec or settings `CheckSettings` refuses; its skills directory is `.claude/skills` and `SessionFiles` merges resolved skill controls into `Settings` at `.claude/settings.json`, plus a `claude-skill-policy.json` receipt and the embedded Lanterns plugin at `.claude/plugins/lanterns`, the settings allowing `guildhall`, read-only `git` and `git remote -v` with no further arguments in Bash, denying direct `guildhall claude-artisan`, `guildhall fake-artisan`, `guildhall fake-director` and `guildhall artisan start` calls with or without arguments via `Bash(<command>:*)` rules that override the broad `guildhall` allow, preserving task orchestration and `artisan stop/status/resume`, denying any `git` command with `--output` (`git diff --output=<file>` writes a file), denying edits to the copy's `config.toml` and `managed.toml` by absolute rule paths, a Windows drive written `//c/...`, and registering `TurnStartCommand`, `guildhall director turn-started` with no path, as the `UserPromptSubmit` hook and `TurnEndCommand`, `guildhall director turn-ended` with no path, as the `Stop` and `StopFailure` hooks, so `TurnEndHook` is true, and `ContextReportCommand` plus `--lanterns`, `guildhall director context-report --lanterns`, as the display-only `statusLine` command.
`ContextReport` is true because the core turn-ended hook supplies transcript context for [automatic handoff](../director.md#automatic-handoff), not because of the status line.
`ParseStatusLine` reads `context_window.used_percentage` from the JSON Claude Code passes a status-line command, rounded to a whole percent and clamped to 0 to 100, reports none without an error when it is absent or null, as before the first message, and refuses input that is not one JSON object ([automatic handoff](../director.md#automatic-handoff)).
`Adapter.Command` passes `Spec.Copy` and `Spec.Profile` as `--copy` and `--profile` before any `--claude`; `ParseArgs` reads the reference, never rules.
`CheckSettings` enforces the Claude [runtime settings](../adapters.md#runtime-settings), with supported efforts declared by `Efforts`, and refuses unsupported values with `adapter.ErrUnsupportedSetting` naming the setting; it does not check that a model exists.
`Command`, `ParseArgs` and `Run` refuse what it refuses, `Command` returning no command; `Command` passes `Spec.Settings` as `--model` and `--effort` after the profile reference and before any `--claude`, `ParseArgs` reads them into `Args.Settings`, and `ClaudeArgs` passes them to Claude Code after `--permission-mode`, each only when set.
`--allow-tool` is a usage error.
`Run` resolves the reference through `adapter.ProfileTools` and materialises exactly the loaded profile's rules, refusing an undeclared profile; without both reference fields it grants nothing.
`TestDirectorCannotPassGrantRules` reproduced the bypass before this fix ([red run](../evidence/artisan-grant-reference-red.txt)); `TestWrapperProfileAuthority` covers empty, undeclared and incomplete references over the stub.
`Run` always merges `ArtisanSettings`, `{"permissions":{"allow":[<rules>]}}`, with the resolved [skill policy](config-claude-skills.md), writing JSON with a newline at `ArtisanSettingsPath`, `ArtisanSettingsFile` (`claude-settings.json`) beside the result file and outside the model directory, even with an empty allow list.
It writes the policy receipt there too, and refuses an unsupported Claude version or conflicting bundle-disable environment before preparing the model directory; the version probe makes no model call.
`Run` consumes newline-delimited Claude stream events incrementally and writes assistant text and one short line per tool call to stdout while the process is running.
The [Claude adapter documentation](../adapters.md#claude-adapter) owns the displayed line format, subject selection and sanitization limits; other event payloads are not displayed.
Only the final result event supplies usage, denials and final result text; earlier stream volume cannot exhaust the final-result capture budget.
Malformed or oversized events are ignored for display and cannot change result publication, cancellation or containment semantics.
Output-consumer failure is presentation-only and cannot stop the Claude process.
`TestReadableStreamBeforeClaudeExits` was written before implementation against the existing Claude process stand-in, extended to emit assistant/tool events, and failed because no readable output appeared before cancellation, then passed ([evidence](../evidence/artisan-workspaces-2026-10-25.txt)).
Supplementary parser tests for oversized and malformed events, byte-by-byte input, command truncation, final usage after a large transcript and sink failure passed on first run.
Existing conformance, usage, denials and owned-launcher tests remain zero-model process checks.

`ClaudeArgs` is print mode with `Instruction`, `OutputFormat` (`stream-json`), `--verbose`, `PermissionMode` (`acceptEdits`), `--settings` with `ArtisanSettingsPath` on every attempt, and only the model directory added; `Instruction` names the prompt copy and the draft (`DraftFile`, in the model directory) on their own lines and fixes the result identity.
The complete result template and matching required output entries come from the rendered prompt, not an adapter-local empty-output example.
For custom prompts without a template, `Instruction` describes adding status, summary and each required file to the fixed identity fields; only failed results or automatic code-head capture may omit required file outputs.
`ParseUsage` reads Claude Code's JSON result message as an `adapter.Usage`: its `usage` tokens measured, its `total_cost_usd` an estimated cost, what it lacks unknown, and output that is not one JSON object or gives an invalid number an error; once Claude exits, unless it was stopped, `Run` writes that usage as the attempt's [usage file](../adapters.md#usage-file), unknown when the output gives none, before publishing the draft (a failure to write it is returned as an error after the draft is still published), and writes the message's `result` text to its stdout, or the output unchanged when it is not a result message, keeping at most 4 MiB of it.
`Denials` reads the result message's `permission_denials` as each denied tool with its command or file, such as `Bash(go test ./...)`, or the tool alone, and none for output that is not a result message; `Run` names them on its stderr ([Artisan permissions](../adapters.md#artisan-permissions)).
`ParseArgs` refuses a prompt inside the model directory; it and `Main` follow the fake's shape: exit 0, 1 on failure, 2 on refused arguments.

## Stable Director workspace

`WorkspaceDir(copyDir)` returns `<copy>/director/claude`.
`PrepareSessionWorkspace` implements [`runtimes.PersistentSession`](adapter-runtimes.md): it stages a copy of the numbered record's `.claude` tree, replaces the workspace's previous generated tree, and returns the workspace path without changing the record.
Copy or publication errors return no working directory; a later call can retry.
See [Director start](../director.md#start) for native folder-trust approval and the supervisor's launch behavior.

`TranscriptContext` reads bounded Claude JSONL usage for the core end-of-turn reporter, independent of Lanterns or a status line.
It selects the latest main-session assistant input plus both cache-input counters against a known model capacity, resets at compaction, and never totals historical requests or counts output tokens.
Unknown model capacities yield no reading.
`TestTranscriptContextUsesLatestMainUsageNotTotals` and `TestTranscriptContextWindowsAndCompaction` were written red first ([evidence](../evidence/lanterns-2026-10-24.txt)).
