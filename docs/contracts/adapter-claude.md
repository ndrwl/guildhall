# `internal/adapter/claude`

## Contract

The minimal Claude Code runtime ([Claude adapter](../adapters.md#claude-adapter)): no optional capabilities; `Adapter.Command` is `guildhall claude-artisan` for a valid spec in its working directory and environment, refusing an invalid spec or an unset executable with no command.
`Run` is the wrapper: it refuses a cancelled attempt (`adapter.ErrAttemptCancelled`) or an existing result (`adapter.ErrResultExists`) without starting Claude, replaces the model directory (`ModelDir`, `artisan.ModelDir` beside the result) with the prompt copy (`PromptCopy`) and the `inputs` and `skills` beside the prompt, runs `claude` (`PATH`, or an absolute `--claude`) with `ClaudeArgs` and no standard input, and once Claude exits publishes the draft's bytes at the result file by hard link, never replacing one and never after the cancel marker; no draft is `ErrNoDraft`.
The cancel marker, an interrupt or the end of its context stops Claude (interrupt on Unix, termination on Windows, a kill after `StopGrace`) and publishes nothing; the marker is not an error.
`ClaudeArgs` is print mode with `Instruction`, `OutputFormat` (`json`), `PermissionMode` (`acceptEdits`) and only the model directory added; `Instruction` names the prompt copy and the draft (`DraftFile`, in the model directory) on their own lines and gives the result object for the attempt's identity.
`Adapter.Session` is the interactive [Director session](../director.md#start): `claude --append-system-prompt-file <role> --add-dir <copy> [--model <model>] <first message>` in the session directory with the session environment, `Program` on `PATH` or an absolute `Claude`, no effort flag, and no command for an invalid spec; its skills directory is `.claude/skills` and `SessionFiles` is `Settings` at `.claude/settings.json`, allowing `guildhall`, read-only `git` and `git remote -v` with no further arguments in Bash, denying any `git` command with `--output` (`git diff --output=<file>` writes a file), denying edits to the copy's `config.toml` and `managed.toml` by absolute rule paths, a Windows drive written `//c/...`, and registering `TurnStartCommand`, `guildhall director turn-started` with no path, as the `UserPromptSubmit` hook and `TurnEndCommand`, `guildhall director turn-ended` with no path, as the `Stop` and `StopFailure` hooks, so `TurnEndHook` is true, and `ContextReportCommand`, `guildhall director context-report`, as the `statusLine` command, so `ContextReport` is true.
`ParseStatusLine` reads `context_window.used_percentage` from the JSON Claude Code passes a status-line command, rounded to a whole percent and clamped to 0 to 100, reports none without an error when it is absent or null, as before the first message, and refuses input that is not one JSON object ([automatic handoff](../director.md#automatic-handoff)).
`ParseUsage` reads Claude Code's JSON result message as an `adapter.Usage`: its `usage` tokens measured, its `total_cost_usd` an estimated cost, what it lacks unknown, and output that is not one JSON object or gives an invalid number an error; once Claude exits, unless it was stopped, `Run` writes that usage as the attempt's [usage file](../adapters.md#usage-file), unknown when the output gives none, before publishing the draft (a failure to write it is returned as an error after the draft is still published), and writes the message's `result` text to its stdout, or the output unchanged when it is not a result message, keeping at most 4 MiB of it.
`Denials` reads the result message's `permission_denials` as each denied tool with its command or file, such as `Bash(go test ./...)`, or the tool alone, and none for output that is not a result message; `Run` names them on its stderr ([Artisan permissions](../adapters.md#artisan-permissions)).
`ParseArgs` refuses a prompt inside the model directory; it and `Main` follow the fake's shape: exit 0, 1 on failure, 2 on refused arguments.

## Tests

`claude_test.go` was written red first against stub bodies ([red run](../evidence/claude-adapter-2026-10-21-red.txt)), every test failing: `adaptertest.RunConformance` as a direct child, on interpreter-rendered attempts and inside the Artisan launcher on this platform's unit, where a stop must end at rung 1; the command and argument parsing; `ClaudeArgs` and `Instruction`; refusals that start nothing; a stale draft never published; and a stop on the context's end.
`session_test.go` was written red first ([red run](../evidence/director-start-2026-10-22-red.txt)): `adaptertest.RunSessionContract` over the stub, red until the stub gained its interactive mode, and the settings golden (`testdata/session-settings.json`), red with no golden; `TestSessionCommand` and `TestSessionSettingsWriteAWindowsCopyInPOSIXForm` were added with the implementation and were not run red; `TestSessionSettingsKeepGitReadOnly`, which evaluates the settings' allow and deny rules for a command, was added when review found `git diff --output` allowed.
The `Stop` hook in the golden and `TurnEndHook` in `TestSessionCommand` were red against the settings without the hook ([red run](../evidence/director-handoff-2026-10-22-red.txt)); the `UserPromptSubmit` hook was added to the golden with the turn-start signal and the `StopFailure` hook when review found a turn ending in an API error sent no turn end; `TestSessionSettingsSignalEveryTurn` reads the hooks back as Claude Code does, each event running its one command, and was not run red.
`TestParseStatusLine` and the `statusLine` in the golden were red against a stub parser and the settings without it ([red run](../evidence/director-handoff-triggers-2026-10-22-red.txt)): the recorded status-line input in `testdata/statusline.json`, written from the input schema Claude Code 2.1.308 documents, reads 71.7 as 72, `testdata/statusline-fresh.json` with a null percent reads as none, rounding and clamping, absent fields as none, and malformed input refused.
A live Claude Code Director session is not run by any test; the Director [safety checks](../director.md#safety-checks) in CI run it over the stub.
`TestParseUsage` and `TestRunWritesUsage` were written red first against a stub `ParseUsage` and a wrapper without `--output-format` ([red run](../evidence/attempt-spend-2026-10-22-red.txt)): the stub's result message read as measured tokens and an estimated cost, a message without a cost or without usage giving unknown numbers, text, empty, doubled and negative output refused, and the usage file written with and without a draft and the result text passed through, but none for a stopped session; `TestClaudeArgs` was red on the added `--output-format json`.
`TestRunPublishesDespiteUsageFailure` and `TestLimitedBufferCapsAChildsOutput` (a child process writing past the cap) were added when review found a usage write failure losing the draft and `exec` bypassing the output cap.
`TestModelDirExcludesControlFiles` was red against the wrapper that added the attempt directory: the only added directory must hold none of the result, cancel marker, outcome, lock, events or launcher log.
All of them run the wrapper over [`claudetest`](adapter-claude-claudetest.md)'s stub; `TestLiveClaude` runs a real session only with `GUILDHALL_CLAUDE_LIVE=1`; it passed on the earlier wrapper, before the model directory, and is pending a re-run on the current wrapper.
`TestDenials` and `TestRunReportsDenials`, over the stub's `denied` behaviour, were added with `Denials` and have no recorded red run; `TestLiveClaudeBuildPermissions` runs a real session asked to run a non-read-only check, `sh check.sh`, and commit, only with `GUILDHALL_CLAUDE_LIVE=1`, and has not been run yet.
`TestArtisanStartRunsClaudeOwned` in `internal/cli` runs `artisan start --adapter claude` over the stub, and `TestTaskStartLaunchesClaude` runs `task start` through `launch.Process` to it from a profile naming `claude`.
