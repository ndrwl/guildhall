# `internal/launch`

## Contract

The composition package behind `artisan start`, `stop`, `status` and `resume` ([commands](../artisan.md#commands)); its [doc comments](../../internal/launch/launch.go) own the API contract.
`Attempt` names an owned attempt by store, state directory and key, with its directory, adapter identity and `Files`.
`Files` is the real `artisan.AttemptFiles`: the adapter's identity-bound, version-checked result and its `.cancelled` sidecar; a missing or invalid result is not valid, an unreadable one is an error, and a late result is still seen while the marker is present.
Result reads use `atomicfile.Open` and its [bounded publication-race retry](atomicfile.md); missing and invalid results retain the classifications above.
`attemptOutcome` is the one translation of a launcher outcome and result into the store's outcome ([glossary](../glossary.md#outcome)).
The [owned command lifecycle](../artisan.md#commands) describes `Run`'s setup, locked takeover, supervision and finalization, including refusal of already-decided attempts.
Worker startup errors, including containment persistence errors, remain in `Run`'s returned error while the launcher decides and writes the outcome and the store records it.
`Run` records a named unit's description (job, cgroup) with the ownership it takes, and the worker identity with `running`, so an owner gone between the two is proven exited by its empty unit; a process group is recorded only with its worker ([limits](../artisan.md#limits)).
`ProbeOwner` is alive while the recorded launcher lives and gone only when it is gone and its recorded unit is proven empty, by `reconcile.ProbeOwner`, the one owner-gone rule.
`Resume` follows the [resume rules](../artisan.md#resume): nothing to do without an unreleased record, refusal of a live or unproven owner, a sweep until the unit is proven empty, then `artisan.Settle` (an owner still `starting` fails with `launcher exited before its worker was recorded`) and `FinishAttempt` under the attempt lock with an idempotent mutation id; `ResumeArgv` is the command a pane registers for it.
`Stop` follows the [command's termination-evidence rules](../artisan.md#commands), returning `ErrNotStopped` when termination is unproven; on a released ownership its `StopReport.Launcher` is `LauncherAdvancing`, `LauncherGone` or `LauncherUnverified` from the recorded launcher's probe.
[`launchtest`](launch-launchtest.md) is the one test cleanup rule for an attempt over `Stop`'s report.
`SweepOwner` is that sweep alone, for an owner recorded outside an attempt, such as a Director session whose supervisor is gone ([director-runtime-record](../decisions/0090-director-runtime-record.md)): it repeats `artisan.Sweep` until `reconcile.ProbeOwner` proves the unit empty, within `ctx` and `SweepTimeout`, returns the processes it swept, sweeps the emptied unit once more to remove what it leaves, and returns `artisan.ErrNotEmpty` naming survivors, the unit's read error, or `store.ErrOwnerUnknown` for an owner not proven gone, sweeping nothing then.
`Status` is `reconcile.Classify` over the attempt's files and ownership record; `Classify` is the same given an ownership record the caller already read, so [`director status`](../director.md#status) classifies every running attempt from one store read.
`Run` and `Resume` record the attempt's spend with `RecordAttemptSpend` just before `FinishAttempt`, in the same store open, from the adapter's [usage file](../adapters.md#usage-file) beside the result (`adapter.ReadUsage`), unknown when there is none or it cannot be read; a refused spend record does not stop the finish and is joined into the returned error.
`Run` and `Resume` rely on the store's [first finish standing](../store.md#attempts): an attempt another writer, such as the interpreter's result intake, already finished with the same outcome is not an error, and another outcome keeps the store's and is returned as an error.
`Process` is the real `interp.Launcher` ([mock agent](../mock-agent.md#the-launch-seam)): `Launch` refuses a spec whose `interp.Spec.AdapterSpec` is outside its manifest's attempt layout, runs `guildhall artisan start` for the attempt with the engine's adapter name unchanged and that adapter spec's prompt file and working directory as a detached process logging to `LogFile`: its own session on Unix, its own process group on Windows, and outside a Director runtime's [session unit](artisan.md) it was started from, created in the cgroup `artisan.DetachCgroupEnv` names on Linux (`CLONE_INTO_CGROUP`) and broken away from the Job Object on Windows (`CREATE_BREAKAWAY_FROM_JOB`), each started where the caller is when that is refused ([decision](../decisions/0084-director-stop-admission.md)); and returns once that process owns the attempt with its endpoint recorded, and at once with an error when that process released the attempt without one, so a launcher whose attempt failed at setup is not waited for while its advance waits for the caller's task lock; a process that does not record its endpoint within `StartTimeout` or before the caller's context ends is stopped, and `Launch` returns its error once that process releases the attempt, without waiting for it to exit; an adapter name [`runtimes`](adapter-runtimes.md) does not hold is refused by that process and is `Launch`'s error naming the log, like any other startup failure; `Stop` addresses only the spawned child's captured PID and process token through its recorded endpoint, waits for that process to exit, and refuses a handle it did not return.
At the shared `Launch` / `LaunchFiles` boundary, the store path is resolved against the caller's working directory before constructing the attempt or child/resume argv, so a pane's working directory cannot reinterpret it.
`Process.Presentation` optionally supplies the terminal boundary (`adapter.TabHost` and agent-report function); `OpenPresentation` resolves it lazily only when launching, so result recording and cancellation do not depend on Herdr.
In presentation mode `Launch` claims `pane-launch.json` exclusively, refuses existing ownership or a prior claim after classifying the attempt, creates a new labelled workspace without focus, opens its Artisan tab, records that binding, registers `ResumeArgv` with source `guildhall`, then types the owned launcher's argv with `--pane-launch`.
The bridge starts the ordinary launcher detached with durable log output and streams that log; the normal owned endpoint, identity, results, spend and watcher remain authoritative.
`StartTimeout` bounds presentation resolution, workspace and tab creation, shell readiness, agent registration, typing and ownership acquisition together; an earlier caller deadline still applies.
Unlike hidden-mode startup cleanup, uncertain pane startup is never stopped speculatively: timeouts and ambiguous API replies retain the claim and return an error, without another launch or tab removal.
No tab disappearance is taken as process exit; `Stop` uses only the ownership record's captured process identity and endpoint.
Finished tabs remain open with a completion line; no presentation path closes any tab.
`Config.Advance`, when set, is the [watcher](../running.md#the-watcher): once `FinishAttempt` records the outcome, `Run` runs the program with `step done` and the attempt's identity and result file after a finished attempt with a valid result, otherwise `task start` with its task, or for a `workflow.JudgeStep` attempt `quality judged` with its task and attempt number whatever its end, the rest of `Advance` before the identity; its output is appended to `LogFile` and `artisan.LogAdvance` logs an `advance` event for each run; a run that fails is run once more, and when that fails too `Run` sends `interp.AdvanceFailedMessage`, naming the command and its last line of error output, through `Config.Outbox`, which takes no task lock; neither changes the outcome nor `Run`'s result.
`Launch` passes the adapter spec's `Copy` and `Profile` as `--copy` and `--profile`, with `--advance` when a copy is present; it never transports rules.
It passes the adapter spec's `Settings` as `--model` and `--effort`, each only when set ([runtime settings](../adapters.md#runtime-settings)), and leaves refusing one to the runtime, whose `artisan start` exits before owning the attempt.
`artisan start` then checks that the copy's store and state are the ones `--store` and `--state` name.
`Config.StallInterval`, positive with an `Outbox`, makes `Run` send the Director `interp.StalledMessage` from the launcher's heartbeat (`artisan.LauncherConfig.Beat`) once per crossing of the interval by the beat's `last_output_at`, which is the newest modification time of `Stdout` and `Stderr` when they are regular files; the send runs on its own goroutine, which `Run` waits for before returning, a beat arriving meanwhile replacing any still waiting, and a failed send is retried on the next beat; `Process.StallInterval`, when positive, is passed as `--stall-interval`.
`Process.LaunchFiles` is `Launch` for an attempt given as its key, adapter name, absolute prompt file and absolute working directory, with no rendered manifest, which a delivered task's [judge](quality.md) uses; it refuses an adapter `interp.CheckAdapter` refuses, a relative path and an ended context, starting nothing, and shares startup with `Launch`, retaining `Process.LockWait`; it passes `Process.Copy` as `--copy` with `--advance` when set, whereas `Launch` passes the adapter spec's copy and profile.
Failed-start cleanup follows the same identity boundary: a refused duplicate never stops the existing owner, and a stale handle never targets a replacement owner.

## Artisan workspace presentation

Each workflow attempt creates its own new workspace labelled `artisan <repository>/<task>/<step>/<attempt>` in the configured non-default session, without focus.
It never reuses the Director workspace or a same-labelled workspace.
The durable single-use claim precedes workspace creation; missing or ambiguous presentation never authorizes another launch.
No automatic workspace cleanup is performed: result recording and work preservation remain prerequisites for any future tool-driven cleanup.
The pane streams the durable launcher log and workspace loss does not affect ownership or task records.
The workspace assertion in `TestWorkflowPaneOwnsLauncherAndClosingDoesNotStopAttempt` was added before implementation and failed on reuse of the Director workspace, then passed ([evidence](../evidence/artisan-workspaces-2026-10-25.txt)).
The additional workspace-create timeout case passed on first run and pins the retained-claim/no-retry rule after an ambiguous workspace response.
