# `internal/launch`

## Contract

The composition package behind `artisan start`, `stop`, `status` and `resume` ([commands](../artisan.md#commands)); its [doc comments](../../internal/launch/launch.go) own the API contract.
`Attempt` names an owned attempt by store, state directory and key, with its directory, adapter identity and `Files`.
`Files` is the real `artisan.AttemptFiles`: the adapter's identity-bound, version-checked result and its `.cancelled` sidecar; a missing or invalid result is not valid, an unreadable one is an error, and a late result is still seen while the marker is present.
Result reads use `atomicfile.Open` and its [bounded publication-race retry](atomicfile.md); missing and invalid results retain the classifications above.
`attemptOutcome` is the one translation of a launcher outcome and result into the store's outcome ([glossary](../glossary.md#outcome)).
The [owned command lifecycle](../artisan.md#commands) describes `Run`'s setup, locked takeover, supervision and finalization, including refusal of already-decided attempts.
Worker startup errors, including containment persistence errors, remain in `Run`'s returned error while the launcher decides and writes the outcome and the store records it.
`Run` records a named unit's description (job, cgroup) with the ownership it takes, and the worker identity with `running`, so an owner gone between the two is proven exited by its empty unit; a process group is recorded only with its worker ([limits](../artisan.md#limits)).
`ProbeOwner` is alive while the recorded launcher lives and gone only when it is gone and its recorded unit is proven empty, by `reconcile.ProbeOwner`, the one owner-gone rule.
`Resume` follows the [resume rules](../artisan.md#resume): nothing to do without an unreleased record, refusal of a live or unproven owner, a sweep until the unit is proven empty, then `artisan.Settle` (an owner still `starting` fails with `launcher exited before its worker was recorded`) and `FinishAttempt` under the attempt lock with an idempotent mutation id; `ResumeArgv` is the command a pane registers for it.
`Stop` follows the [command's termination-evidence rules](../artisan.md#commands), returning `ErrNotStopped` when termination is unproven.
`Status` is `reconcile.Classify` over the attempt's files and ownership record; `Classify` is the same given an ownership record the caller already read, so [`director status`](../director.md#status) classifies every running attempt from one store read.
`Run` and `Resume` rely on the store's [first finish standing](../store.md#attempts): an attempt another writer, such as the interpreter's result intake, already finished with the same outcome is not an error, and another outcome keeps the store's and is returned as an error.
`Process` is the real `interp.Launcher` ([mock agent](../mock-agent.md#the-launch-seam)): `Launch` refuses a spec whose `interp.Spec.AdapterSpec` is outside its manifest's attempt layout, runs `guildhall artisan start` for the attempt with the engine's adapter name unchanged and that adapter spec's prompt file and working directory as a detached process (its own session on Unix, its own process group on Windows) logging to `LogFile`, and returns once that process owns the attempt with its endpoint recorded, and at once with an error when that process released the attempt without one, so a launcher whose attempt failed at setup is not waited for while its advance waits for the caller's task lock; an adapter name [`runtimes`](adapter-runtimes.md) does not hold is refused by that process and is `Launch`'s error naming the log, like any other startup failure; `Stop` addresses only the spawned child's captured PID and process token through its recorded endpoint, waits for that process to exit, and refuses a handle it did not return.
`Config.Advance`, when set, is the [watcher](../running.md#the-watcher): once `FinishAttempt` records the outcome, `Run` runs the program with `step done` and the attempt's identity and result file after a finished attempt with a valid result, otherwise `task start` with its task, the rest of `Advance` before the identity; its output is appended to `LogFile` and `artisan.LogAdvance` logs an `advance` event, and its failure changes neither the outcome nor `Run`'s result.
`Process.Copy`, when set, adds `--copy <dir> --advance` to the launcher's argv; `artisan start` then checks that the copy's store and state are the ones `--store` and `--state` name.
Failed-start cleanup follows the same identity boundary: a refused duplicate never stops the existing owner, and a stale handle never targets a replacement owner.

## Tests

The original cases were written red first against stub bodies, every case failing; the red runs are in the pull request description.
Review regressions were added later.
`TestProcessDuplicateLeavesOwnerRunning` starts a real hanging worker, attempts a duplicate through another `Process`, verifies the original endpoint still serves status and ownership remains unreleased, then checks explicit and repeated stops.
The corrected regression reads ownership by its actual attempt key.
See the [authorized retrospective comparison](../evidence/s7-review-retrospective.md) for the evidence and its limitations.
`outcome_test.go` is the translation table over every launcher state and result.
`files_test.go` reads missing, malformed, other-attempt, newer-version and draft results as not valid, a valid result before and after the marker, an idempotent marker, and refuses another attempt's marker; `TestStopContractRealFiles` runs `artisantest.RunStopContract` with `Files` on this platform's units, the test binary playing a worker that publishes a real version 1 result and honours the sidecar.
`files_windows_test.go` exercises the real `Files.Result` and `Files.ValidResult` readers while an exclusive Windows handle temporarily blocks opening the published result.
`TestStopContractRealFiles` also runs the shared suite's Windows held-result case; on the native Windows host it failed three of three runs with the sharing violation when `Files.Result` used `os.Open` (the same failure as this pull request's first CI run, L16), and passed three of three with `atomicfile.Open`.
`launch_test.go` runs owned attempts against a real store with real units and processes: a succeeded and a failed result finished and recorded with the ownership released naming the launcher, endpoint and containment; a worker exiting without a result failed; a live owner refused with nothing started and the record unchanged; a stop through the endpoint cancelled at rung 1 and recorded stopped, and a second stop refused while the released launcher still lives; the context ending the attempt past rung 1; a stop without an owner only classifying; and a silent live owner not stopped and not marked.
`recovery_test.go` checks refused takeover without recorded containment, successful takeover with an emptied real unit, terminal decisions with live owners, missing containment, surviving workers or verified empty units, and preservation of endpoint stop failures.
`takeover_lock_test.go` checks that a run waits for locked outcome publication and refuses the resulting decision, and that lock contention respects a caller deadline without changing ownership or starting a worker.
`decided_test.go` checks that finished, cancelled and failed outcomes refuse a recovery run without changing ownership, containment evidence, the persisted outcome or the store attempt, both with a usable endpoint path and one blocked by a directory.
`setup_failure_test.go` checks that an overlong endpoint path leaves no ownership or worker and permits a corrected retry, and that a blocked endpoint bind records a failed attempt and releases ownership without starting a worker.
`start_failure_test.go` is a review regression: a nonexistent working directory preserves the startup error, writes the failed outcome, records the failed store attempt and releases ownership without starting a worker.
`resume_test.go` was written red first against a stub `Resume` ([red run](../evidence/launcher-resume-2026-10-21-red.txt)): no owner does nothing; a live launcher and a gone launcher without containment are refused with the tree alive, no outcome and the record unchanged; a gone launcher with a surviving tree, an emptied unit with a result, a surviving tree with the marker, and an outcome already decided are swept, settled, recorded and released, and a second resume finds the record released.
`starting_gap_test.go` was written red first (sustainability review 8, F20; [red run](../evidence/owner-starting-gap-2026-10-21-red.txt)): a launcher process whose unit kills it as it starts the worker (`DieAtWorkerStart`, through the unexported unit factory in `export_test.go`) leaves an owner in `starting`; on a named unit it is classified `exited`, `resume` settles it failed with `launcher exited before its worker was recorded` and releases it, and `start` takes it over and runs a worker; on a process group the record holds no containment and both refuse it as unverified, the documented window.
The expected kind comes from a fresh unit, not the record: a first draft that read the record passed vacuously before the change.
On Linux with delegated cgroup v2 both named cases were red, the record holding no containment.
`TestStopContractFakeArtisan` runs `artisantest.RunStopContract` with the fake Artisan as the worker through the fake adapter's command (F2); it was red against the fake without the P0 directives, while the cases that start no worker or need no directive (the three L15 cases, an invalid result and a decided attempt) passed.
`process_test.go` was written red first against stub bodies: `TestProcessPassesLauncherContract` runs `interptest.RunLauncherContract` against `Process`, the test binary playing `guildhall`, and failed four of six cases (the invalid-spec and foreign-handle refusals passed against the stubs); `TestProcessLaunchFailsWhenTheLauncherExitsFirst` failed on the missing launcher log; `TestProcessRefusesASpecOutsideItsAttemptLayout` passed against the stubs, which refused everything, and pins the layout refusals; its adapter case left with the adapter list (sustainability review 9, F28), and refusing an unknown adapter is now `TestArtisanStartRefusesAnUnknownAdapterByName` in `internal/cli`.
`TestProcessStartsArtisanStartOnTheAdapterSpec` passed on first run, since the adapter spec maps the files unchanged ([run](../evidence/stall-adapter-choice-2026-10-22-red.txt)): it pins the launcher's argv, the adapter name unchanged and `interp.Spec.AdapterSpec`'s prompt file and working directory, over the test binary recording its arguments and refusing them, which `Launch` reports with the log's name.
`advance_test.go` was written red first ([red run](../evidence/launcher-watcher-2026-10-22-red.txt)) with the test binary playing `guildhall step done` and `task start` and recording, as it starts, its arguments, `outcome.json` and the store's outcome and ownership: a finished attempt with a succeeded or a failed result runs `step done` once with its result file, a worker exiting without a result and a stop through the endpoint each run `task start` once, always after the outcome is published, recorded and released, never while the attempt runs; each logs one `advance` event and its output in `launcher.log`; a failing advance (exit 3) leaves `Run`'s result, the stored outcome and the release as they were, with its exit status in the event.
`TestRunWithoutAdvanceRunsNone` passed against the stubs, since a nil `Advance` already ran nothing.
`TestProcessAsksAnEngineCopysLauncherToAdvance` pins the argv with `Process.Copy` set, `--copy <dir> --advance` after the existing flags.
`TestTheWatcherReportsASetupFailure` in `internal/cli` is a review regression written red first ([red run](../evidence/launcher-watcher-2026-10-22-red.txt)): from a copy, a directory at the plan attempt's endpoint path fails the attempt at setup; `task start` reported the launch error only after 30 seconds, `Launch` waiting for the launcher while the launcher's `task start` timed out on the task lock, and no `attempt-failed` was sent; it now returns the error within ten seconds and the launcher's advance sends the Director `attempt-failed` for the failed attempt.
`intake_race_test.go` was written red first: a launcher finishing an attempt the interpreter already finished with the same outcome reported the store's refusal; with another outcome it still reports an error and keeps the store's.
It passed first through a tolerance in `Run` and now pins the store's rule, which replaced it.
`TestArtisanStartCustody` in `internal/cli` is the launcher and store custody acceptance: a launcher process owns a fake worker while separate processes read its status, send a message, answer a decision and are refused a competing run, each within ten seconds and leaving the ownership record unchanged; a stop through the endpoint then ends it with exit status 5.
After the red commit the launcher gained one event: `rung-emptied` for rung 1 when the marker empties the tree before the ladder's first check, which the stop contract already required and the real files' slower marker write exposed.
