# `internal/store`

## Contract

`Open`, locking, mutation ids and receipts, and the records, messages, inboxes and workflow approvals (`docs/store.md`, D9, D10, D15, D22), including typed decisions bound to a subject with option-checked answers (D23), Director rulings recorded once and contested once with the review projection on document references ([director-rulings](../decisions/0040-director-rulings.md)), full-review requests requested and consumed once ([full review](../tasks.md#full-review)), and receipts naming their record with `TaskHistory`'s one-transaction task read (D24) and `DirectorView`'s one-transaction read of the whole store for [`director status`](../director.md#status).
Attempt ownership ([store-attempt-ownership](../decisions/0031-store-attempt-ownership.md)): `Ownership`, `StartOwnedAttempt`, `TakeOwnership` with its required `OwnerProbe` seam, `ProbeLauncher` over a caller-supplied `IdentityProbe`, the store-neutral `ProcessIdentity` and `Liveness` values and `ErrOwnerLive`/`ErrOwnerUnknown` refusals, `UpdateOwnership`, `Ownership`, and release by `FinishAttempt`.
The ownership record's `Containment` is a recovery description of every Artisan containment kind ([containment-persistence](../decisions/0037-containment-persistence.md)): `Containment.Recoverable` and `ErrUnrecoverable`, the kind constants, a worker identity in place of a name for process groups, the Linux detection reason, and legacy records read unchanged but never recoverable when incomplete.

Director sessions and wakes in the `director` bucket ([director-session-record](../decisions/director-session-record.md)): `StartDirectorSession` numbered from 1 and superseding every earlier session that has not stopped, `SetDirectorState`'s forward-only moves with `running` and `paused` moving to each other and a compare-and-set on `StateSequence`, `DirectorSession` and `LatestDirectorSession`; `RecordWake` once per message to the Director with `WakeFor` and ordered, bounded `Wakes`; `DirectorUnread`'s counts by type, which the [wake](../messaging.md#waking-the-director) types; and `DirectorView.Session`, the newest session read in the view's transaction.

The [attempt ownership contract](../store.md#attempt-ownership) defines monotonic recovery evidence, `ProbeLauncher`'s containment refusal and the explicit containment-aware recovery path.

## Tests

Real bbolt files: `store_test.go`, `records_test.go`, `messages_test.go`, `approvals_test.go`, `history_test.go`, `ownership_test.go`, `process_test.go` (separate processes, including a take-over refused while another process owns the attempt and allowed once it is killed), `fixture_test.go` (schema v1 file), `rulings_test.go`; full-review requests are pinned by the store run of `interptest.RunRecordsContract`

`TestFinishAttemptFirstFinishStands` was written red first ([red run](../evidence/finish-first-stands-2026-10-21-red.txt)), with the equal-outcome case of `RunRecordsContract`: a second finish with an equal outcome under a new mutation id returns the first finish's receipt, writes no receipt and takes no sequence number; another outcome is refused with `ErrInvalid`.

`director_test.go` was written red first against stub bodies ([red run](../evidence/director-session-2026-10-22-red.txt)) on real store files: a session starting `recovering`, surviving a restart and replaying; every start refusal writing no receipt; the state table, each refused move leaving the session and receipts unchanged; the ready and end times, a stale move refused and a missing session not found; a second session superseding the first while a stopped session is left as it ended; wakes recorded once per message, a second decision conflicting, ordered and paged; every wake refusal; and the schema 1 fixture accepting both records.
`TestDirectorUnreadCountsByType`, which counts unread messages by type across repositories, was red in the same run and lands with the wake that uses it.

`director_view_test.go` was written red first against a stubbed `DirectorView` ([red run](../evidence/director-status-2026-10-22-red.txt)): an empty store's empty lists and zero snapshot, and across two repositories every task and attempt in key order, only the unreleased owner, only the open decisions, only the Director's unacknowledged messages in send order, and only the receipts that name a task.

`rulings_test.go` was written red first against stubbed `RuleFinding` and `ContestRuling`: each refusal (unknown move, blank reason, preset contest, deferring a rule-cited finding, unknown finding, document or task, a document without a projection), replay, a second ruling, contesting once, `TaskHistory`'s rulings and the projection's validation.
The ownership tests were written red first against stubbed methods: refusing a live owner, refusing an unknown owner, allowing a take-over after proven exit, release by `FinishAttempt`, replay by mutation id, the second-process refusal, one-mutation start with crash rollback, validation, one winner among concurrent take-overs, and doctor counts.
The containment record tests were written red first against a stubbed `Recoverable`: named and nameless round trips (`TestContainmentRoundTrips`), refusal of incomplete evidence (`TestContainmentRequiresRecoveryEvidence`), and a legacy record that stays readable while its incomplete group evidence refuses a take-over (`TestLegacyContainmentRecords`).
`TestUpdateOwnership` and `TestOwnershipValidates`'s two existing containment cases are retrofit pins that still hold for named kinds.
`TestTakeOwnershipAfterProvenExit` recorded a process group by its group id as a name; that expectation was wrong under this contract, and the test now records the group by its worker identity.
`TestTakeOwnershipPreservesContainmentAfterLauncherExit` pins refusal and intact persisted evidence for every containment kind with a dead launcher and a surviving worker, through the native launcher probe and a `ProbeLauncher` whose identity probe calls every process gone, followed by explicit recovery after worker exit.
The monotonic evidence rule was written red first: `TestUpdateOwnershipKeepsRecoveryEvidence` refuses clearing containment, changing its kind or worker, and clearing or changing the endpoint, each leaving the record unchanged and no receipt; `TestProgressUpdateCannotEraseRecoveryEvidence` in `process_test.go` refuses a real launcher's progress update that drops its containment, then refuses a take-over through the same two probes while the recorded worker survives.
Sustainability review 8, F20, was written red first ([red run](../evidence/owner-starting-gap-2026-10-21-red.txt)): `TestTakeOwnershipRecordsANamedUnitBeforeItsWorker` takes ownership with a cgroup and no worker, refuses a process group without one, refuses renaming, clearing or re-kinding the unit while adding the worker, adds the worker once with `running`, and refuses clearing it again; it was red on adding the worker.
`TestDoctorCountsOwnersStartingWithoutContainment` counts an owner in `starting` with no containment apart from one with a named unit, and not once it is running; it was red on the count.
`Containment.Recoverable` already accepted a job or cgroup without a worker, so its cases there pin rather than change it.
`TestProbeLauncherAgainstRealProcesses` pins the scratch launcher's owner cases (a live owner refused; a reused PID with another token taken over).
Store-neutral owner value tests: `TestStoreDoesNotImportArtisan` (dependency direction), `TestTakeOwnershipRequiresProbe` (nil-probe refusal), `TestProbeLauncherNeverClassifiesSurvivorsGone`, and the no-verdict case of `TestTakeOwnershipRefusesUnknownOwner`.
