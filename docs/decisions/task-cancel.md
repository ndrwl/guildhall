# Task cancel

Guildhall had no way to end a task without delivering it, so dropped tasks sat in every list with open decisions or parked attempts.
`guildhall task cancel --repo <repo> <task> --reason <text>` now ends an open task for good, at the Guildmaster's request ([task cancel](../tasks.md#task-cancel)).

## Decisions

- **One command, reason required, irreversible.** A cancelled task is never advanced, judged, audited or un-cancelled; wanted work becomes a new task.
- **A separate store operation.** `CancelTask(mutation, repo, task, reason)` sets `cancelled`, `cancel_reason` and `cancelled_at`, rather than a reason on `SetTaskState`'s request, so the request digest of every `done` close and deliver's replay are unchanged. Its receipt counts toward `handoff_after_tasks` as `set-task-state` does.
- **Void, not answered.** `VoidDecision` marks an unanswered decision `void` with a reason; `Decision.Open` (neither answered nor void) replaces `!Answered` wherever a decision is tested as waiting: `director status`, the dependency gate, `decide list` and the merge queue's front wait. `AnswerDecision` refuses a void decision.
- **`decide answer` refuses a cancelled task's decisions, not a done task's.** The spec said "a closed task"; a done task's `audit` decision is answered after it merged ([quality](../quality.md)), so refusing every closed task would break audits.
- **Forge `Close`.** `gh pr close <n> --repo <r> --comment "Cancelled by Guildhall: <reason>"`, never `--delete-branch`; an already closed pull request is success and a merged one `ErrRefused`. The branch and the local worktree are kept (see Prune below).
- **Every recorded pull request is closed, not only the latest.** The task's `-pr` documents are read once per remote and number; publish rounds and rebase links normally name the same pull request, and closing a closed one changes nothing, so this needs no notion of "latest".
- **Order: stop, close, then the records.** The spec listed the merged-PR refusal first and the close after voiding decisions and leaving the queues, but the forge offers no read of a pull request's state besides `Close` itself. Closing before any record of the task changes means a pull request merged on the forge refuses the cancel before decisions are voided or queues left, which would otherwise strand an open task with decisions no one could answer; only the stops already made stand, and the Director can retry them. Stops still come first, so an unproven stop refuses the cancel with nothing else changed. A `-merge` document refuses before anything.
- **Refuse an unproven stop.** When `launch.Stop` cannot prove an Artisan stopped (`ErrNotStopped`) the cancel is refused and the task stays open, keeping the invariant that a cancelled task has no live Artisan. A Director stage's attempt has no owner and is recorded `stopped` by the cancel.
- **The state change is last.** Each write has a mutation id `cancel.<repo>.<task>.<part>`, and messages and closes are replay-safe, so a cancel that fails part-way is finished by running it again.
- **Dependents are told, not cancelled.** One `dependency-cancelled` message per open dependent in any listed repository, id `<repo>.<task>.dependency-cancelled.<cancelled repo>.<cancelled task>`, so a re-run resends nothing; the dependency gate's own `dependency-held` text and ids are unchanged.
- **A cancelled task's advance succeeds quietly.** Stopping an owned attempt makes its launcher run `task start`, which would fail twice and send `advance-failed`. `task start` and `step done` of a cancelled task print `task <repo>/<task> is cancelled; nothing to advance` and exit 0, whatever the order of the cancel and the launcher's advance; a done task's advance still fails. The launcher records the attempt's outcome itself before advancing, so nothing is lost.
- **Unread messages still count.** A cancelled task's unread messages stay in `director status`'s `messages` item until read (open question 1, accepted).
- **Prune.** d46's prune landed first, so d47 makes it select `cancelled` tasks as it selects `done` ones, `prune_after` after the `cancel-task` receipt that set `cancelled_at`, with a void `audit` no longer holding a task. Its attempt files are pruned; its worktree and branch are not, because `Retire` removes a worktree only at the head a `-merge` document names and a cancelled task has none. Removing unmerged work was not specified, so the worktree is kept with `the task was cancelled unmerged, …` as its reason, the daily prune tells the Director once, and the Director decides.
