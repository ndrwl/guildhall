Reading:
- The Stop hook fired. Only `guildhall result hook` sends `t1.plan-1.nudge.submit`, and the store holds it, from
  guildhall, type nudge. The session ended its first turn with "stopping" and no draft, so the hook found no valid
  result, sent the nudge and printed {"decision":"block","reason":...}.
- The block continued the --print session. After "stopping", with no new input, the model ran the ack the nudge's
  text names, wrote the draft and submitted it, so the block reason reached it as its next turn.
- It ended after one nudge. At the second stop the draft was valid, so the hook printed nothing and the session
  exited; the wrapper published the result. The test leaves no trace of the second hook run itself; the hook
  tests (TestResultHookLeavesAValidDraft, TestResultHookStopHookActive) pin that path.
- Q1's "acknowledge, then submit" text worked: the model acked before it submitted, and the submission was accepted.

An earlier run the same day, with a prompt that asked for an empty outputs list, showed the same continuation
("stopping", then the ack and a submit). Intake then rejected the submissions three times because the fixture's plan
step requires a spec output. The wrapper published the 3rd rejection's draft, as it does without the nudge. The
prompt was then changed to list the pre-written spec.md, which gave the run above.
