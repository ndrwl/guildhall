# Research

Learn what the change will touch before anyone plans it.
Read the parts of the repository the task concerns, its documents and its tests.
Record how the relevant code works today, what the change must keep working and any risk you found.
Cite files and lines rather than paraphrasing them.
Write the required `notes` port as a UTF-8 Markdown document at `notes.md` in your working directory.

When a merged pull request of this repository already shipped everything the task asks for, write no notes and report `failed` with an `already-delivered` outcome naming it in `by_pr`, as the Result template shows; when the task needs no change at all, report `failed` with a `nothing-to-do` outcome saying why.
Start the summary with `Already delivered by <pr url>` or `Nothing to do`, then give the evidence.
